# 站点与供应商接入模块设计

> 模块定位：维护站点、共享供应商资料、模型、采购价格、加密凭证和逐站投放关系
> 对应代码：`internal/domain/site`、`internal/domain/supplier`、`internal/domain/operations`、`internal/application/onboarding`、`internal/application/operations`、`internal/platform/crypto`、`internal/adapters/storage/postgres`、`db/migrations/00003_m1_site_identity.sql`
> 所属里程碑：[M0 - 跑通单站供应商接入闭环](../roadmap.md#m0)、[M1 - 跑通多站人工运营闭环](../roadmap.md#m1)
> 当前状态：已完成
> 最近更新时间：2026-09-05

## 1. 职责与边界

本模块负责：

- 保存 New API 站点的稳定身份、名称、地址和管理凭证。
- 保存供应商资料、OpenAI 兼容地址、上游凭证、模型和采购价格。
- 建立供应商投放到站点的关系，并保存专属分组、销售倍率、入口开放状态和接入状态。
- 对敏感凭证加密、版本化和脱敏，向同步用例提供短生命周期的解密结果。
- 提供 M0 管理接口，让运营人员完成站点、供应商和投放关系录入。
- 在一次业务事务中保存投放关系并触发首份单站线路方案。

本模块不负责：

- 直接拼装或发送 New API 请求。
- 计算评分、Auto 成员、主动测评和动态价格。
- 管理 New API 用户、用户 API Key、余额、订单或计费流水。
- 保存 New API 管理凭证或供应商密钥的明文副本。

## 2. M0 业务流程

```text
录入站点
   │
   ├─ 校验 New API 地址
   └─ 加密保存管理凭证
             │
录入供应商   │
   │         │
   ├─ 校验地址、模型和价格
   └─ 加密保存上游凭证
             │
             ▼
      创建站点供应商关系
             │
             ├─ 生成稳定专属分组标识
             ├─ 生成稳定渠道受管标记
             └─ 请求生成线路方案
```

M0 允许先录入一个站点和一个真实供应商。数据从第一天保留多站、多模型和一个供应商对应多个实际渠道的结构，M1 增加数量时不迁移核心关系。

## 3. 核心数据

### 3.1 站点

| 字段 | 含义 | 规则 |
|---|---|---|
| 站点身份 | ManyRouter 内部主键 | UUID，创建后不变 |
| 站点代码 | 运营使用的稳定代码 | 小写字母、数字和连字符，全局唯一 |
| 名称 | 运营展示名称 | 可以修改，不参与资源认领 |
| New API 地址 | 管理接口根地址 | 只允许 HTTP/HTTPS，规范化后保存并全局唯一，去掉末尾斜杠 |
| 管理凭证 | 当前凭证引用 | 指向加密凭证版本 |
| 状态 | 是否允许生成和执行新同步 | `enabled`、`disabled` |
| 兼容状态 | 最近能力检查结果 | `unknown`、`compatible`、`incompatible` |
| 数据版本 | 防止旧请求覆盖新配置 | 每次修改递增 |

迁移 `00003_m1_site_identity.sql` 为规范化后的 `new_api_base_url` 建立唯一索引，同一保存地址无法登记为两个站点，创建和修改都会受到数据库约束。该索引只能识别规范化结果完全相同的地址；不同域名、IP 或其他地址别名仍可能指向同一个 New API 实例，运营人员录入前必须确认目标进程、配置和业务数据库彼此独立。

### 3.2 供应商

| 字段 | 含义 | 规则 |
|---|---|---|
| 供应商身份 | ManyRouter 内部主键 | UUID，创建后不变 |
| 供应商代码 | 稳定业务代码 | 小写字母、数字和连字符，全局唯一 |
| 名称 | 运营展示名称 | 可以修改 |
| 接入协议 | 首个供应商协议 | M0 只开放 `openai_compatible` |
| 上游地址 | 供应商 API 根地址 | 只允许 HTTP/HTTPS；末尾标准 `/v1` 自动去掉，由 New API 拼接实际接口路径 |
| 上游凭证 | 当前凭证引用 | 指向加密凭证版本 |
| 状态 | 全局接入状态 | `draft`、`enabled`、`disabled` |
| 数据版本 | 并发修改保护 | 每次修改递增 |

供应商模型独立保存模型名、上游模型名、输入采购价、输出采购价、币种和启用状态。金额使用十进制，禁止用二进制浮点数计算。

### 3.3 站点供应商关系

| 字段 | 含义 |
|---|---|
| 关系身份 | 一次供应商投放的稳定 UUID |
| 站点身份、供应商身份 | 唯一组合，禁止重复投放 |
| 专属分组内部名 | 由关系身份生成，创建后不随展示名变化 |
| 专属分组展示名 | 运营和后续页面使用的名称 |
| 销售倍率 | M0 由运营人员明确填写并确认 |
| 入口开放 | 是否允许用户选择及继续调用该专属分组；关闭后已有该组密钥也会被拒绝 |
| 期望状态 | `observing`、`enabled`、`disabled` |
| 同步状态 | `pending`、`syncing`、`active`、`failed`、`manual_locked` |
| 当前线路版本 | 最近生成的期望状态版本 |
| 最近确认时间 | New API 重新读取并核对成功的时间 |

M0 为每份关系建立一个实际渠道记录。该记录已经独立成表，后续可以在同一个专属分组下增加协议或模型拆分渠道。

## 4. 稳定标识

- 专属分组内部名使用 `mr_s_` 加关系 UUID 的 32 位十六进制形式。
- New API 渠道标签使用 `manyrouter:` 加关系 UUID。
- 展示名称只用于人读，查找和认领受管资源只能使用已保存绑定或稳定渠道标签。
- 同一站点出现多个相同受管标签时停止自动修改并记录冲突，禁止猜测应保留哪一个。
- 删除关系后重新接入会获得新的关系身份，旧用户选择不会悄悄指向新资源。

## 5. 凭证保护

- 供应商密钥和 New API 管理令牌使用 AES-256-GCM 加密。
- 主密钥通过 `MANYROUTER_MASTER_KEY` 注入，内容为 32 字节密钥的 Base64 编码。
- 每份密文使用独立随机数，并把凭证身份、用途和密钥版本作为附加校验数据。
- 数据库存储密文、随机数、密钥版本、创建时间和撤销时间，不存储明文。
- 解密只发生在执行对应站点同步的短生命周期内，日志和错误响应统一清洗。
- 修改凭证新增一个版本；旧版本在新版本同步确认前保留，M0 暂不开放自动轮换流程。

## 6. 管理接口

M0 提供以下 `/api/v1` 接口：

| 接口 | 用途 |
|---|---|
| `POST /sites` | 新增站点并保存管理凭证 |
| `GET /sites/{site_id}` | 查询站点和兼容状态 |
| `POST /suppliers` | 新增供应商、模型、价格和上游凭证 |
| `GET /suppliers/{supplier_id}` | 查询脱敏后的供应商资料 |
| `POST /site-suppliers` | 创建投放关系并生成首份线路方案 |
| `GET /site-suppliers/{relation_id}` | 查询投放、线路和同步结果 |

写接口要求运营令牌和 `Idempotency-Key`。M0 使用部署环境中的单一所有者令牌保护管理接口；完整运营账号、服务端会话和控制台在 M1 开始前进入对应模块设计。服务默认只绑定受保护网络地址。

## 7. 关键决策

1. 站点、供应商和投放关系使用独立身份，后续多站扩展不复制供应商资料和密钥。
2. 供应商上游凭证只维护一个有效来源，各站 New API 保存同步后的运行副本。
3. M0 的销售倍率由运营人员填写；M1 由稳定价格模块保存独立价格版本，动态报价进入后续里程碑。
4. 投放关系创建与首份线路方案生成使用同一个数据库事务，避免出现有关系却没有目标配置的半成品。
5. 接口响应从不回传凭证明文；重复提交通过幂等键返回第一次业务结果。

## 10. M1 扩充设计

### 10.1 职责划分与目录

沿用现有站点、供应商领域和接入应用目录；列表查询、资料修改、批量投放、启停和凭证轮换按用例拆分文件，存储查询继续通过 sqlc 生成。供应商凭证预检通过独立接口调用上游，HTTP 细节放在适配层。预检只验证人工接入操作，M2 的持续采集与测评另行设计。

- 本模块维护供应商共享资料、采购价、凭证、投放身份和逐站展示意图。
- [人工策略管理](./人工策略管理.md)维护各站固定 Auto 的成员；本模块提供可投放、可启用的供应商清单。
- [稳定价格管理](./稳定价格管理.md)维护各站销售价格及其版本；接入模块只引用当前价格版本。
- [单站线路方案](./单站线路方案.md)汇总完整站点配置；[New API 同步与核对](./New%20API同步与核对.md)负责外部执行和实际生效结果。
- 写操作使用[运营账号与权限](./运营账号与权限.md)提供的身份，列表和操作结果由[运营控制台](./运营控制台.md)展示。

### 10.2 数据扩充

| 对象 | M1 新增或调整 | 约束 |
|---|---|---|
| 站点 | 可编辑资料、实际管理账号编号、管理凭证更新记录 | 账号编号不再固定为 `1`；地址和账号变化必须先通过只读鉴权与能力检查 |
| 供应商 | 资料编辑、模型维护、全局启停、候选凭证与轮换记录 | 共享资料只存一份；删除已投放供应商使用停用，保留历史身份 |
| 投放关系 | 编辑、批量创建、逐站启停、恢复原因、明确的人工锁记录 | 保留已有唯一关系和稳定分组名；各站展示、策略和售价独立 |
| 批量投放 | 请求身份、供应商、目标站点、逐站结果及生成的计划编号 | 唯一目标去重；同一批次与站点只创建一次结果 |
| 凭证轮换 | 候选凭证引用、预检结果、目标版本、逐站确认和退出原因 | 密文沿用现有凭证表；旧凭证被引用期间保留 |
| 实际渠道 | 最近确认的凭证身份与版本、停用来源、最近确认配置摘要 | 凭证版本确认独立于可读渠道字段，避免更换密钥后被误判成无变化 |

供应商业务版本与凭证版本分开递增。资料更新携带读取时的业务版本，版本已变化返回冲突及最新版本；服务端不静默覆盖。采购价格修改保留审计，但不自动调整站点售价。

### 10.3 批量投放与修改流程

1. 供应商资料录入一次，批量请求列明目标站点及各站展示、售价和启停配置。
2. 投放意图在一个短数据库事务中保存，生成各站独立的关系、价格引用、完整站点计划、同步操作和 River 任务；事务内不调用外部接口，业务校验或保存失败时整次投放意图回滚。
3. 事务提交后的外部同步逐站独立，某站失败不回滚其他站。按站点返回“已受理、已生效、失败、等待处理”；受理成功不代表外部配置已经生效。
4. 外部失败时重试对应站点，成功站点保留结果。重复提交同一投放请求复用首次保存结果，进程退出后由持久任务继续同步。
5. 修改全局地址、模型或启用状态时，在同一业务事务内保存供应商新版本，并为所有受影响站点生成计划和任务；受影响站点按固定顺序加锁。事务不调用外部接口。
6. 仅修改某站展示或投放状态时，只生成该站计划；仅修改供应商运营备注或采购价格时，没有实际线路差异便不生成计划。

M0 的关系创建入口继续保留，M1 内部转为单个目标站点的同一流程。保存意图与任务入队必须通过同一 PostgreSQL 事务完成，避免保存成功后因进程退出而漏掉同步。

### 10.4 启停与恢复

| 操作 | 行为 |
|---|---|
| 暂停站点管理 | 阻止该站新的外部写入，已在 New API 运行的服务保持现状；恢复管理后按最新计划核对 |
| 停用某站供应商 | 该站计划明确标记渠道停用，并移除其有效 Auto 成员资格；无需上游可用即可下线 |
| 全局停用供应商 | 所有已投放站点生成停用计划，分别显示实际生效进度；失败站点持续保留未完成状态 |
| 恢复投放 | 校验全局供应商有效、站点可写、模型与价格有效，经测试后启用；其他站点不受影响 |
| 解除 New API 人工停用 | 必须单独提交显式恢复动作及原因；普通资料编辑、策略更新和密钥轮换均保留人工锁 |

站点暂停管理与供应商下线分别提供操作，不把“暂停同步”显示为“已停止用户调用”。停用不硬删除渠道或分组，用户已持有的分组选择不自动转向其他供应商。停用造成 Auto 无可用成员时，按策略模块规则停用该组并保留售价。

### 10.5 凭证轮换

供应商换密钥采用“保存候选版本、预检、发布目标版本、逐站确认”的流程：

1. 新密钥先通过供应商模型列表接口完成鉴权预检，成功后加密保存为候选版本；真正的模型可调用性由各站同步测试确认，不把鉴权通过描述成模型调用已通过。
2. 预检失败保留旧版本；预检成功后，业务事务记录供应商候选凭证版本，为所有已投放站点生成新计划和任务。当前有效凭证在各站全部确认前保持旧值。
3. 同步模块必须比较目标凭证版本与逐渠道已确认版本。即使地址、模型与分组均相同，密钥变化也要下发。
4. 每站成功写入、测试并核对后，单独记录确认；某站失败不撤回其他站已确认的新密钥。暂停管理或被人工锁住的站点保持待处理，不算轮换完成。
5. 旧密钥在所有相关渠道完成新版本确认前保留；停用中的已有渠道也计入确认范围，尚未创建外部渠道的占位关系不算运行副本。全部已有渠道确认后，锁定供应商记录并把候选提升为当前有效版本。ManyRouter 不替运营人员撤销供应商后台的旧密钥。
6. 新版本发布后不自动回退凭证。确需回退时，旧版本必须尚未撤销并重新预检，通过新的轮换操作生成新线路版本；旧任务无权重发旧密钥。

候选下发未完成期间仍允许紧急全局停用；运营人员也可提交更高版本的新候选来替换失败候选。取消轮换前，先检查当前旧密钥仍可通过上游鉴权，再清除候选并生成新的回退计划。已经使用候选的站点通过新计划逐站切回，不能直接把历史任务重新入队当作回退。

被替换或取消的候选密钥会立即在本地加密凭证库标记撤销，后续任务不能再读取。站点管理凭证通过新地址、账号和只读权限检查后切换，本地保存的上一管理凭证同时标记撤销；跨地址修改未提供新凭证时在外发请求前拒绝，避免把当前站点令牌发送到新主机。

预检会产生一次真实上游鉴权请求，结果仅证明该时刻模型列表接口接受此凭证。同步中途失败仍可能留下逐站差异，控制台必须显示这些差异。站点管理令牌轮换只影响对应站点：用候选令牌与配置的账号编号完成只读检查后切换，下次任务读取当前有效管理令牌，禁止历史计划恢复旧管理令牌。

### 10.6 管理接口与验收

M1 在已有 `/api/v1` 下补齐站点、供应商、投放关系列表及修改接口，独立提供批量投放、启停、恢复、候选凭证预检和发布接口；具体请求响应由 OpenAPI 同步定义。列表支持站点、供应商、启停状态、同步结果筛选和游标分页，凭证始终只显示存在状态、版本和最近结果。

写接口沿用幂等键，新增预期版本和操作原因。重复请求复用首次结果；相同幂等键携带不同内容返回冲突。批量接口返回各站计划和同步结果入口，不用单个成功标志掩盖失败站点。

配置发布使用快速数据库锁。相同请求、全局配置或目标站点正在被其他操作处理时立即返回“配置处理中”，运营人员稍后重试；等待者不会长期占用数据库连接。旧 M0 关系入口也使用相同锁，并在锁内重读站点、供应商、模型和候选凭证状态；若与锁前准备内容不同便返回配置冲突，重新读取后再提交，防止并发停用或换密钥被旧内容覆盖。

M1 必须验证：

- 按[统一验收口径](../需求设计.md#m1-acceptance-scope)建立 3～5 个独立供应商记录，允许服务地址、访问密钥和模型复制自同一真实上游；记录身份、内部代码、投放关系及受管分组分别独立。
- 两个站点必须对应配置和业务数据库隔离的独立 New API 实例；不能把同一地址复制为两个站点，地址别名指向同一实例也不计入双站。
- PostgreSQL 集成测试使用相同规范化 New API 地址创建两个站点，第二次写入必须命中 `sites_new_api_base_url_unique`；地址别名的实例身份继续由运营核实。
- 每个供应商记录的资料与凭证可以跨站复用，各站入口开放状态、售价和启停互不覆盖。
- 批量投放意图保存、逐站外部失败、重复请求和处理中断后继续，不重复创建关系或丢失任务。
- 供应商更新、完整站点计划和任务在事务内一同成功或回滚，并拒绝过期编辑。
- 上游故障时仍可下线，普通编辑不解除人工停用；恢复需重新验证。
- 新密钥预检失败保留旧版本，仅凭证变化也下发；部分站点失败、暂停站点、旧版本撤销和显式回退均有正确结果。
- 更新站点管理凭证时，非默认管理账号编号和鉴权失败可明确反馈，任何响应与审计均不含密钥。

验收报告分别记录供应商记录数与真实上游数，标明复制记录的共同来源。该场景验证多记录管理和多站投放，不证明多个真实厂商的独立故障、采购成本或模型能力差异；真实供应商多样性留待后续运营验证。已有上游鉴权或线路关闭测试也不能被记录为多个厂商之间的真实故障隔离。

## 11. M1 当前实现与验收结果

- 已扩展站点管理账号编号和逐渠道凭证确认记录，数据库可保留当前与候选凭证。

- 已通过迁移 `00003_m1_site_identity.sql` 固定站点地址唯一约束，阻止同一规范化 New API 地址被多个站点同时认领；地址别名仍执行人工独立实例检查。

- 单站失败隔离及恢复、独立入口开关和历史恢复已通过，M1 接入扩充完成。该结果验证多记录管理，不作为多个真实厂商的故障、成本或能力差异证据。
