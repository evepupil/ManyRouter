# M1 多站点策略运营

> 模块定位：在 M0 单站接入基础上，实现多个 New API 站点的统一供应商投放、站点独立策略与价格，以及可人工运营的多站产品闭环。

## 1. 职责与边界

本模块负责在 ManyRouter 中统一管理多个 New API 站点的供应商投放和站点级策略。运营人员添加或修改供应商后，可以选择目标站点，由平台自动建立和维护各站点所需的渠道、供应商专属分组、价格及策略关系。

模块需要维护站点、供应商、专属分组、固定 Auto 分组和实际渠道之间的对应关系，并允许每个站点独立决定：启用哪些供应商、启用哪些固定 Auto、是否显示供应商专属分组，以及使用哪份站点销售价格。

M1 的 Auto 由运营人员人工维护成员，平台提供配置、状态查看和同步能力。评分、模型真实性、主动测评、自动准入退出和自动恢复属于 M2、M3；用户自定义 Auto 属于 M5。

模块还负责为后续请求、成本、收入、成功率和延迟统计建立准确的站点归属，并保证共享供应商资料与站点用户、余额、订单、销售价格之间隔离。完整的日志增量采集、统计结果和影子评分在 M2 交付。

## 2. 结构与数据流

```text
ManyRouter 统一供应商资料与共享凭证
             │
             ├──────────────► 站点 A 的供应商关系
             │                    └─专属分组、固定 Auto、站点价格
             │
             └──────────────► 站点 B 的供应商关系
                                  └─专属分组、固定 Auto、站点价格

运营人员修改站点策略
             │
             ▼
只为受影响站点生成期望配置
             │
             ▼
各站点独立同步到 New API
             │
             ▼
逐站读取实际状态、核对并记录结果
```

同一供应商默认跨站共用一个上游账号和访问凭证。各站点的 New API 仍保存实际调用所需的凭证副本，ManyRouter 记录每个站点已同步的凭证版本。站点身份、日志来源和渠道绑定用于区分站点表现，不依赖不同上游密钥进行归因。

新增供应商时，平台先保存统一供应商资料，再为每个目标站点生成站点供应商关系和受管资源计划。某个站点失败时，其他站点可以继续完成；失败站点保留待同步状态并独立重试。

策略修改只传播到受影响站点。供应商专属分组被隐藏时，只改变用户可见和可选状态，不删除分组、渠道、历史统计或绑定关系。

## 3. 关键决策

- 供应商基础资料和默认上游凭证只维护一份；站点使用关系、展示方式、价格和策略参与情况分别保存。
- 一个供应商在一个站点仍然只有一个用户可理解的专属分组；同一供应商需要多个实际渠道时，由平台维护多个渠道与该分组的绑定。
- 固定 Auto 是站点级产品。平台统一维护策略定义，每个站点决定是否启用、展示和允许哪些供应商参加。
- M1 采用人工策略运营，运营人员可以调整固定 Auto 成员、供应商可见性、站点价格以及停用和恢复状态；自动评分和自动成员变化留给后续里程碑。
- 站点价格与供应商排名、线路成员变化分开管理。线路或成员变化不直接导致用户价格频繁变化。
- ManyRouter 与各 New API 之间采用最终一致。每个站点单独生成、执行和核对配置，单站失败不得阻塞其他站点。
- New API 受管资源与普通资源严格区分。同步任务只能修改已建立绑定或明确接管的资源。
- 各站点用户、余额、订单、销售价格和利润相互隔离；共享供应商统计不得泄露其他站点的用户和经营信息。
- 运营账号独立于任何一个 New API 站点，站点接入凭证按站点隔离并可单独撤销。

## 4. 当前实现

当前尚未实现本模块代码。M1 依赖 M0 已完成的单站接入、受管资源绑定、期望状态核对和真实调用能力。

规划中的职责分布如下：

- 站点领域模块维护站点身份、站点启用状态和站点范围。
- 站点供应商模块维护供应商在各站点的启用关系、专属分组、渠道绑定和同步结果。
- 策略模块维护固定 Auto、供应商可见性、候选范围和人工成员调整。
- 价格模块维护供应商专属分组和固定 Auto 的站点销售价格及生效状态。
- 多站投放用例负责一次供应商变更对多个站点的影响范围和逐站执行。
- 控制台提供站点、供应商、策略、价格、可见性和同步结果的管理入口。

## 5. 验证方式

退出 M1 前必须使用同一套 ManyRouter 与受支持的 New API 组合，建立至少两个真实站点，并接入 3～5 家真实供应商验证完整业务链。

- 在 ManyRouter 中录入一次供应商，至少两个目标站点自动出现对应渠道、专属分组和价格，无需进入站点后台重复配置。
- 多站点使用同一供应商账号和凭证时，能够记录各站点已同步的凭证版本，并保证站点、供应商、渠道和后续统计归属关系正确。
- 修改站点 A 的供应商范围、固定 Auto、专属分组可见性或销售价格时，站点 B 不发生无关变化。
- 隐藏供应商专属分组后，用户侧不可选择该分组，但受管渠道、历史记录和绑定关系仍保留。
- 人工增加、移除固定 Auto 成员或停用供应商后，目标站点的 New API 配置能够完成同步并经过重新读取核对。
- 一个站点 New API 不可达或同步失败时，其他站点仍能完成同步和服务；失败站点的未完成事项可单独重试。
- ManyRouter 停止后，各站点 New API 继续使用最后一次有效配置处理已有请求。
- 站点经营数据和用户范围数据不会在控制台、用户接口或统计结果中串站。
- 所有跨站投放、人工调整、价格变化和失败重试都有可查询的业务原因、站点结果和操作记录。

## 6. 待扩展项

- M2 增加独立日志库只读采集、完整测量事实、主动测评和影子评分，为自动运营提供可信依据。
- M3 将固定 Auto 的人工维护升级为按规则自动准入、退出、全局停用和恢复。
- M3 增加固定 Auto 自动运营以及用户侧 SLA、延迟、质量和报价展示。
- M4 增加正式批量同步、兼容矩阵和组合发布。
- M5 增加用户自定义 Auto、稳定报价确认、策略快照和不同用户策略隔离。
- 后续可增加多地区测评、更多站点品牌、供应商自助录入、其他网关和独立站点执行节点。
