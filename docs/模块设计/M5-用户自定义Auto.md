# M5 用户自定义 Auto

> 模块定位：让用户按价格、延迟、SLA 和质量四项偏好创建自己的 Auto 策略，获得稳定报价并绑定到专用 API Key。

> 技术依据：[技术设计](../技术设计.md)

## 1. 职责与边界

本模块负责用户级 Auto 偏好、报价、策略保存和 API Key 绑定，具体包括：

- 让用户调整价格、延迟、SLA 和质量四项占比。
- 确保四项占比合计为 100%。
- 根据最新有效数据给出自定义 Auto 的预估结果和报价。
- 用户确认报价后保存策略，并创建绑定该策略的 API Key。
- 将已确认策略编译为带版本的本地策略快照，供 New API 在请求过程中读取。
- 保证不同用户的策略和报价互不影响。

本模块不负责供应商评分事实、固定 Auto 的公共成员维护、New API 用户基础账户与计费规则，也不改变模型请求的统一入口。模型真实性、凭证、余额和连续失败等硬性门槛始终优先于用户自定义权重。

## 2. 结构与数据流

### 2.1 用户创建策略

```text
用户调整四项占比
        │
        ▼
ManyRouter 根据最新有效数据计算预估结果和报价
        │
        ▼
用户查看并确认报价
        │
        ▼
保存用户策略与价格版本
        │
        ▼
生成带版本的本地策略快照
        │
        ▼
New API 创建绑定该策略的 API Key
```

用户侧通过 New API 的登录身份进入页面，页面请求经过 New API 用户数据代理访问 ManyRouter。ManyRouter 只返回该用户有权查看和使用的策略、报价及统计信息。

### 2.2 请求执行

```text
用户客户端 + 自定义 Auto API Key
                │
                ▼
             New API
                │
                ▼
        读取本地策略快照
                │
                ▼
       按当前快照选择可用渠道
                │
                ▼
       转发、计费并写入请求日志
```

请求过程中不等待 ManyRouter 实时计算、报价或返回候选线路。ManyRouter 在请求链路之外更新后续可用的策略快照；快照同步失败时，New API 继续使用上一份已确认快照。

### 2.3 评分与报价关系

用户权重只影响通过硬性门槛后的综合偏好和报价。供应商或模型遇到真实性不通过、凭证失效、余额耗尽、连续失败达到停用标准或其他重大风险时，不能因为用户降低某项权重而继续进入自定义 Auto。

## 3. 关键决策

- 四项偏好固定为价格、延迟、SLA 和质量，合计必须为 100%。
- 报价综合考虑预计采购成本、风险准备、支付与运营成本及平台利润，并保留合理的成本波动空间。
- 供应商成员变化和日常排名变化不直接触发用户价格变化；主要供应商采购成本显著变化时，平台才调整报价。
- 用户确认后形成有效策略和价格版本，变更需要保留生效时间与历史记录。
- 自定义策略可以复用内容相同或足够接近的策略，用户的使用体验不能因此改变。
- New API 只读取已经下发到本地的策略快照，请求过程不调用 ManyRouter。
- 自定义 Auto 继续使用 New API 的统一 API Key、分组和转发能力，ManyRouter 不接管用户账户、余额、订单和计费流水。
- 用户自定义策略仍受站点策略、可见范围、供应商资格和硬性排除条件约束。

## 4. 当前实现

ManyRouter 工程尚未创建，本模块暂无实现。当前已有设计只确定四项占比、稳定报价、API Key 绑定和本地快照方向，尚未形成可运行的用户交互、策略计算、报价确认或 New API 本地读取能力。

## 5. 验证方式

- 验证四项占比的输入约束、保存和重新打开后的结果一致。
- 使用真实评分和价格数据验证预估报价、用户确认、价格版本和生效时间能够被正确记录。
- 验证不同用户可以保存不同权重和报价，互不覆盖或串用策略。
- 验证自定义策略不会绕过模型真实性、凭证、余额、连续失败和人工停用等硬性门槛。
- 验证策略快照成功下发后，New API 可以在请求过程中使用本地快照；ManyRouter 不在线或无法实时响应时，请求仍能按上一份快照继续执行。
- 验证 API Key 绑定的策略与用户可见策略一致，策略版本变化不会错误影响其他用户。
- 验证报价在有效期间保持稳定，供应商成员小幅变化不会引起无依据的价格变化。
- 验证用户侧只能看到允许公开的价格、策略和统计，不能获取供应商密钥、真实采购成本、内部评分细节或检测内容。
- 通过核心策略计算、报价、版本切换和快照读取的单元测试，以及真实 New API 集成验证。

## 6. 待扩展项

- 支持更多用户可配置的服务偏好，但必须继续遵守平台硬性门槛和稳定报价原则。
- 在真实运营需求出现后，支持企业策略、地区策略或其他站点级限制。
- 在明确出现规模压力后，优化相同策略的复用和快照分发。
- 与更多兼容网关的本地策略读取能力集成。

这些扩展不得把同步远程调用、临时评分或长时间等待 ManyRouter 引入用户请求链路。
