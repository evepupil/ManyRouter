# 运营控制台

> 模块定位：为所有者提供多站供应商、人工 Auto、价格及同步运营入口。
> 对应代码：`web/`。
> 所属里程碑：[M1 多站人工运营](../roadmap.md#m1)。
> 当前状态：已完成
> 最近更新时间：2026-09-05
> 设计依据：[架构设计](../架构设计.md)、[技术设计](../技术设计.md)、[设计系统](../../DESIGN.md)。

## 职责与边界

控制台展示服务端业务对象并提交运营命令，不在浏览器决定渠道实际状态、不保存明文凭证、不计算采购与销售规则。所有业务请求经同源 `/api/v1` 接口发送。供应商与模型是公共资料，投放、Auto、售价及线路归属于明确站点。

M1 包含所有者初始化和登录、站点与供应商编辑、多站投放、人工 Auto 成员、站点独立售价发布、线路版本恢复、同步及审计查询。自动评分、自动选线及用户自定义策略不进入本模块的 M1 界面。

## 结构与数据流

| 目录 | 职责 |
|---|---|
| `web/src/app/` | 路由、登录状态、当前站点及应用外壳 |
| `web/src/api/` | 管理接口类型、请求处理与错误转换 |
| `web/src/components/` | 统一基础组件、表格、表单及状态 |
| `web/src/features/auth/` | 初始化、登录与退出 |
| `web/src/features/sites/` | 站点列表、接入资料与凭证更新 |
| `web/src/features/suppliers/` | 供应商、模型采购价与密钥轮换 |
| `web/src/features/deployments/` | 多站投放、启停和专属入口 |
| `web/src/features/auto/` | 站点人工 Auto 及成员 |
| `web/src/features/pricing/` | 站点售价草稿、发布与历史 |
| `web/src/features/operations/` | 线路版本、恢复、同步及审计 |
| `web/src/styles/` | 主题 Token、布局和基础组件样式 |
| `web/src/i18n/` | 中文文案与国际化入口 |

页面读取当前会话与站点范围，以 TanStack Query 管理请求与刷新。编辑先保留表单数据，提交成功后清除编辑态并刷新列表；接口返回冲突时保留输入并提示重新读取。价格使用字符串贯穿表单与请求。同步操作显示服务端的真实状态，不由浏览器倒计时推断成功。

## 页面与流程

### 初始化与登录

读取初始化状态，未初始化时收集所有者名称、密码及部署配置要求的初始化凭证；已初始化时显示登录。会话采用服务端安全 Cookie，业务界面通过会话接口决定是否显示；退出后清空业务查询缓存。错误在表单附近展示，不在控制台日志打印凭证。M1 只开放所有者初始化、登录、退出和会话；管理员及观察员仅预留后端结构，账号管理页面不属于本里程碑。

### 站点与供应商

站点列表显示名称、地址、启用状态及兼容结果，详情支持资料和凭证更新。供应商列表显示地址、模型数量、状态及凭证版本；详情单独维护模型名称、上游名称、输入采购价、输出采购价、USD/CNY 币种与启用状态。密钥轮换使用独立动作，列表区分生效版本与待同步候选版本；候选密钥可替换或取消，提交后清空敏感输入。

### 多站投放

选择供应商和一个或多个站点，设置该站点展示名、销售倍率及专属入口是否开放。投放结果逐站展示，每站可独立同步。已投放记录支持上线、下线和专属入口设置，售价通过独立草案发布流程维护。列表和差异使用“入口开放/入口关闭”；关闭时明确提示该组已有密钥也无法调用，确认按钮标明关闭动作。

### 人工 Auto

限定当前站点，列表显示 Auto 名称、状态、用户入口和成员数量。成员仅从该站已投放供应商中选择；M1 统一使用渠道级优先级与权重，不展示按策略单独设置权重的假能力。Auto 入口使用“用户入口开放/用户入口关闭”，关闭同样影响该组已有密钥，提交前明确提示。

### 售价与线路

售价按站点分组维护销售倍率，草稿保存和发布是两个动作；历史记录显示已发布、已核对及已被替代的版本。服务端返回的最近确认标记用于显示“最近确认”，核对时间表示该版本最近一次成功核对的历史时间；新计划待同步或部分写入失败时，不把该记录视作当前外部价格。模型计价依据由服务端记录，控制台不把模型采购价当作用户售价。线路版本显示修改原因、时间与状态，详情以业务差异表比较供应商投放、启停、入口开放与关闭、倍率、上游地址、模型映射、密钥版本、优先级、权重与 Auto 成员；首次版本展示初次配置，跨站或不支持的快照明确报错。恢复历史线路时显示目标站点和版本，由服务端创建新版本并同步。

### 同步与审计

同步表格展示站点、对象、提交时间、执行步骤、尝试次数和结果，进行中的任务定时刷新。审计按站点及动作查询，展示操作者、对象、原因和时间。恢复失败需要人工动作时展示服务端提供的原因，不无限自动重试。

## 关键决策

- 统一复用主题 Token 与基础组件，采用紧凑的列表、页内编辑与必要对话框。
- 手机表格只有明确标为操作的列固定在右侧，行操作无需先横向滚动；数据区保留可见横向滚动条及键盘滚动入口。
- 全部写入对话框在提交期间禁止 Escape、遮罩点击及关闭按钮退出，防止丢失尚未完成的操作上下文。
- 浏览器不持久保存运营密码、上游密钥或会话令牌。
- 请求错误统一处理，未认证回到登录；网络失败不丢失当前表单。
- 未确认成功的写操作在当前编辑流程内保留请求编号；路径、方法和提交内容相同时复用，内容变化或成功确认后换新。旧请求的回执不能清除较新请求的编号，防止响应丢失后重试重复创建价格草案或恢复版本。
- 当前站点始终可见，禁止把上一站点的查询缓存和提交目标混用。
- 站点范围分别表达读取中、读取失败、无站点、待选择和可操作状态；失败保留重试入口，不能显示成“请选择站点”。
- 加载骨架包含状态角色、礼貌播报及读屏文字“正在读取数据”，不依靠颜色或空白表达等待状态。
- 投放候选只允许启用站点被选中，刷新后自动剔除已停用或已移除的站点，空选择禁止提交。投放与 Auto 候选列表区分加载、失败和真实空结果。
- 移动导航使用带焦点约束的对话框；关闭后不保留可 Tab 的抽屉内容，打开时背景不参与焦点导航，关闭后焦点返回菜单按钮。
- 核心业务规则由后端实现并测试；前端承担输入约束、可访问状态和业务流程连通。

## 当前实现

已完成 React 19、TypeScript 严格模式与 Rsbuild 工程、主题 Token、基础组件及八类业务页面。路由与请求使用 TanStack Router/Query，导航文案通过 i18next 装配；Base UI 提供对话框与图标提示。

所有页面使用实际 `/api/v1/auth` 与 `/api/v1/ops` 接口。会话使用服务端 Cookie，写操作发送防重标识和 CSRF 校验；初始化、登录和退出均由服务端确认。前端业务类型由 `api/operations.yaml` 生成，列表显式请求每页 20 条，站点选择与投放选择请求最多 100 条；M1 小规模运营范围内不引入无限列表。

本地预览可通过 `MANYROUTER_API_TARGET` 指定独立后端，默认值为 `http://127.0.0.1:8080`；代理保留浏览器请求主机，确保服务端同源校验一致。调试时显式指定隔离端口，禁止误用已有服务。

保存失败保留输入；投放、同步及恢复提交后只反馈已提交同步。站点投放、Auto、售价及线路页面切换站点时重建其编辑状态。同步列表与运行中任务详情定时读取服务端结果。未知状态显示待核对，未知执行步骤和审计动作使用通用中文名称。

核心逻辑现有 18 条测试：线路差异 7 条覆盖初次配置、密钥轮换、模型顺序、M0/M1 兼容、Auto 成员、跨站拒绝及移除配置；投放选择 4 条覆盖停用、失效、重复及主动清空；站点状态 3 条覆盖读取失败、加载和空选择；请求编号 4 条覆盖失败重试、内容变化、成功清除及较旧回执。2026-09-05 复核修复后已通过 TypeScript 严格检查、18 条核心测试、格式检查和生产构建；此前正式接口类型生成也已通过。

2026-09-05 在隔离 PostgreSQL 数据范围、独立 ManyRouter 后端和 Windows Edge 上完成 9 项界面检查：所有者登录、表单建站、编辑停用、真实接口分页、供应商及 CNY 模型采购价录入、真实重复标识错误且保留输入、全部业务导航、手机菜单与长名称、退出后的服务端会话失效。桌面 1440×1000 与手机 390×844 的 10 处布局检查均无页面横向溢出，5 项文字对比度为 5.39–10.93。截图与报告位于 `.impeccable/review/`。

## 验证方式

- TypeScript 严格模式检查、生产构建通过。
- 执行 `pnpm --filter @manyrouter/web generate` 从正式接口生成类型，`check` 检查严格类型，`test` 验证业务差异，`format:check` 检查格式，`build` 生成生产资源。
- 使用实际管理接口验证初始化、登录、建站、供应商维护、投放、Auto、售价、线路恢复和同步查询。
- 桌面与移动端截图检查导航、长文本、表格横向滚动、对话框、加载、空状态和接口失败。
- 核查密钥不回显、不进入 URL、日志或浏览器持久存储。
- 纯主题、配色和布局不写单元测试；业务结果以服务端测试及浏览器流程验收为准。
