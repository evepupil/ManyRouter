# M3 固定 Auto 自动运营

> 模块定位：把 M2 的观测和影子评分建议转成五种固定 Auto 的自动准入、退出、停用和恢复，并在 New API 中完成可核对的线路同步；同时提供固定 Auto 所需的用户数据代理与页面展示。
> 对应代码：尚未创建；计划目录：`internal/domain/strategy/`、`internal/domain/routing/`、`internal/domain/pricing/`、`internal/application/reconciliation/`、`internal/transport/http/`、`internal/jobs/`、`web/`；New API 用户侧页面和代理改动位于独立适配仓库。
> 所属 M 里程碑：[M3](../roadmap.md#m3)
> 当前状态：未开始
> 最近更新时间：2026-09-04
> 架构依据：[架构设计](../架构设计.md)、[策略架构](../架构设计.md#18-策略架构)、[稳定价格架构](../架构设计.md#19-稳定价格架构)、[New API 配置同步架构](../架构设计.md#20-new-api-配置同步架构)、[用户请求与用户页面](../架构设计.md#21-用户请求与用户页面)
> 技术依据：[技术设计](../技术设计.md)

## 1. 职责与边界

### 1.1 负责内容

- 维护最低价、低延迟、高 SLA、高质量和均衡五种固定 Auto。
- 根据 M2 的评分建议、硬性排除结论和站点策略计算 Auto 成员资格。
- 自动处理供应商进入观察、进入 Auto、退出 Auto、全局停用和恢复。
- 为各站点生成固定 Auto 的期望线路状态。
- 通过 New API 现有管理接口应用受管分组和渠道变化，并重新读取核对实际状态。
- 记录每次自动调整的原因、依据、版本、影响站点和执行结果。
- 保持站点之间的策略、可见性、价格和同步状态相互隔离。
- 保持固定 Auto 的有效价格与线路成员变化分离。
- 提供用户侧读取固定 Auto 价格、可用供应商数量、SLA、延迟、质量和更新时间所需的数据服务。
- 配合 New API 用户侧同源代理和页面展示，并提供数据暂时不可用时的降级状态。

### 1.2 不负责内容

- 不提供用户自定义四项权重和用户级 Auto 报价，这些内容属于 M5。
- 不在用户请求过程中实时调用 ManyRouter 或重新计算评分。
- 不修改 New API 业务主库，不直接改表或依赖缓存内部结构。
- 不自动覆盖运营人员设置的人工安全停用。
- 不因 Auto 成员的普通变化直接调整用户价格。
- 不管理未标记为 ManyRouter 受管的渠道、分组和其他 New API 资源。

## 2. 结构与数据流

```text
M2 影子评分、主动测评和状态结论
                 │
                 ▼
站点固定策略与运营规则
                 │
                 ▼
Auto 成员资格判断
                 │
                 ▼
站点期望线路状态
                 │
                 ▼
读取 New API 实际状态并计算差异
                 │
                 ▼
调用 New API 管理能力应用变化
                 │
                 ▼
重新读取、核对、记录审计与告警
                 │
                 ▼
固定 Auto 对外提供新请求使用
```

用户侧展示单独走数据链路：

```text
New API 用户页面
        │ 当前登录用户身份
        ▼
New API 同源用户数据代理
        │ 站点身份与用户范围
        ▼
ManyRouter 用户数据服务
        │
        ▼
价格、供应商数量、SLA、延迟、质量和更新时间
```

### 2.1 固定 Auto 成员调整

每次评分或状态变化形成站点级决策。平台先执行真实性、凭证、余额、连续失败和人工风险等硬性排除，再按照固定策略的业务目标确定成员资格。成员变化形成新的期望状态，只有受影响站点进入同步流程。

供应商退出 Auto 时，默认保留供应商专属分组；全局停用、人工安全停用和供应商模型异常可以按对应范围停止相关渠道。自动恢复必须经过连续检查，不能覆盖人工安全停用。

### 2.2 配置同步与核对

- 同一站点同时只处理一份正在执行的期望状态。
- 写操作带稳定操作编号，重复执行不会重复创建或反复产生无意义变化。
- 接口接受不代表同步完成，重新读取实际状态一致后才标记成功。
- 多站点同步彼此独立，单站点失败只进入该站点重试和告警。
- New API 暂时不可访问时保留旧的已确认状态，不能把计划状态显示为已生效。
- M3 延续 M0 的现有管理接口路径；正式窄权限批量端点属于后续正式集成范围。

### 2.3 价格与线路

固定 Auto 的价格来自当前有效价格版本。线路成员可以随评分变化调整，价格继续沿用有效版本。只有采购成本出现普遍或显著变化，或运营人员明确调整价格时，才进入价格变更流程。用户侧只能看到已确认生效的价格和更新时间。

## 3. 关键决策

- 固定 Auto 的成员变化由 M2 的观测结论和本站点策略共同决定，不能绕过真实性、凭证、余额、连续失败和人工风险等硬性条件。
- 自动运营只修改 ManyRouter 明确受管的资源，并通过 New API 的业务管理能力完成写入；写入后必须重新读取核对。
- Auto 成员变化、价格版本和用户展示状态分别记录。成员变化不会直接触发用户价格变化。
- ManyRouter 不进入用户请求实时链路。用户页面通过 New API 同源代理读取允许公开的数据，代理不可用时不能影响模型调用。
- M3 只覆盖固定 Auto；用户自定义权重和报价保留到 M5，正式批量接入端点与兼容发布保留到 M4。

## 4. 五种固定 Auto

### 4.1 最低价

在满足必要的真实性、可用性和安全门槛后，优先选择成本较低的合格供应商。

### 4.2 低延迟

优先选择首字时间较短、总耗时较低且波动较小的合格供应商。

### 4.3 高 SLA

优先选择成功率较高、限流较少、容量更稳定且恢复表现更好的合格供应商。

### 4.4 高质量

优先选择模型真实性和能力表现更好的合格供应商。真实性不通过的模型不能进入任何 Auto。

### 4.5 均衡

在价格、延迟、SLA 和质量之间按站点当前策略保持平衡。具体权重、门槛和观察条件由运营规则配置并在后续模块细化。

五种 Auto 都受硬性排除条件约束。用户选择某种偏好不能绕过模型真实性失败、凭证失效、余额耗尽、严重连续失败或人工重大风险。

## 5. 自动状态处理

### 5.1 准入

供应商或供应商模型需要先经过观察，满足当前站点固定策略的准入条件后，才进入对应 Auto。样本不足、数据过期、同步状态未确认或存在硬性风险时，只保留观察或排除结论。

### 5.2 退出

表现跌破退出条件、延迟持续异常、余额接近风险值、连续失败或模型质量异常时，供应商可以退出对应 Auto。普通退出不影响其专属分组，除非另有全局停用结论。

### 5.3 全局停用

模型严重冒充、凭证失效、余额耗尽、供应商失联或确认存在重大风险时，平台对供应商或对应模型执行全局停用，并停止其参与所有相关 Auto。全局问题与单站点局部问题分开处理。

### 5.4 恢复

自动停用对象需要经过连续主动检查和必要的真实表现确认，才能重新进入观察或 Auto。运营人员人工停用的对象只能由运营人员解除安全锁。

### 5.5 防止反复变化

准入、退出和恢复均需要遵守观察期、样本要求和连续窗口确认。数据长时间未更新时，冻结自动扩张和自动恢复，可以执行有依据的安全退出。

## 6. 用户数据代理与页面展示

### 6.1 数据范围

用户侧可以查看当前站点允许公开的固定 Auto 产品信息：

- Auto 名称和当前价格。
- 当前可用供应商数量。
- SLA、延迟区间、质量等级和统计更新时间。
- 数据不足、正在观察或近期异常等状态。

供应商凭证、真实采购成本、内部评分细节、检测题目和未公开的故障信息不得经过用户侧代理。

### 6.2 身份与隔离

- New API 负责确认当前登录用户。
- ManyRouter 负责确认站点身份和允许返回的数据范围。
- 用户侧请求只能读取当前站点和当前用户允许的数据。
- 代理失败或 ManyRouter 暂时不可用时，页面显示数据暂时无法更新，New API 的模型调用继续运行。

### 6.3 展示原则

页面展示的价格必须是已确认生效的版本，统计信息必须带更新时间。Auto 成员内部变化不应造成用户看到的价格频繁跳动；页面需要能区分当前可用、观察中、暂时不可用和数据过期状态。

## 7. 当前实现

- ManyRouter 尚未创建运行代码，本模块当前只有需求、技术、架构和 roadmap 依据。
- New API 适配仓库尚未实现固定 Auto 自动同步、用户数据代理或用户页面展示。
- M2 的真实观测和影子评分尚未完成，因此 M3 暂不能开始自动准入、退出和恢复。
- 当前没有完成 New API 真实线路变更、故障切换、页面代理或降级行为验证。

## 8. 验证方式

### 8.1 逻辑验证

- 用确定性样例验证五种固定 Auto 的业务目标和硬性排除条件。
- 验证准入、观察、退出、全局停用、自动恢复和人工安全停用之间的状态边界。
- 验证普通退出保留供应商专属分组，严重问题可以按范围执行全局停用。
- 验证重复执行、版本冲突、部分站点失败和旧状态保留行为。
- 验证 Auto 成员变化不会自动触发价格变化。

### 8.2 New API 集成验证

- 使用真实 New API 进程验证渠道和分组读取、成员变化、状态处理、倍率保持和重新核对。
- 验证连接失败、首字前失败和允许重试的请求能够使用其他合格线路完成。
- 验证 ManyRouter 停止、站点管理端不可达和同步部分失败时，已有用户请求继续使用最近一次已确认配置。
- 验证非受管资源不被同步任务修改，人工安全停用不会被自动恢复覆盖。

### 8.3 用户侧验证

- 使用真实登录用户验证同源代理返回的站点范围和用户范围。
- 验证价格、供应商数量、SLA、延迟、质量和更新时间与已确认版本一致。
- 验证数据不足、数据过期和 ManyRouter 暂时不可用时页面有明确状态，且不影响模型调用。
- 使用真实浏览器检查页面的加载、空数据、错误、长文本和不同尺寸显示。

### 8.4 M3 退出标准

- 五种固定 Auto 能按规则自动准入、退出、停用和恢复。
- 首字前故障在 New API 允许重试时能够切换并完成请求。
- 每次自动调整都经过实际状态重新读取核对，并保存可查询的原因和结果。
- 线路成员变化不会直接改变用户价格。
- 固定 Auto 所需的用户数据可以通过 New API 用户数据代理展示，代理故障不会影响用户请求。

## 9. 待扩展项

- 用户自定义四项权重、用户级策略快照和动态 Auto 报价，进入 M5。
- New API 正式窄权限批量同步端点和更完整的兼容矩阵，进入 M4。
- 更多地区策略、供应商自助入驻、公开供应商排行和其他网关。
- 同一供应商多套独立凭证、跨站统一账户和更大规模的站点运营。

上述扩展不能破坏固定 Auto 的硬性排除、人工安全停用、价格稳定和用户请求链路独立运行等约束。
