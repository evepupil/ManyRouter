# 用户产品数据与 New API 页面模块设计

> 模块定位：把最近确认的线路、价格和 M2 观测整理成站点用户可读的固定 Auto 产品数据，并通过 New API 当前登录状态安全展示
> 对应代码：`internal/domain/catalog`、`internal/application/catalog`、`internal/adapters/storage/postgres/catalog_source.go`、`internal/adapters/storage/postgres/catalog_snapshot.go`、`internal/adapters/storage/postgres/catalog_tokens.go`、`internal/transport/http/catalog.go`、`api/catalog.yaml`、`new-api/service/manyrouter`、`new-api/controller/manyrouter.go`、`new-api/web/src/features/manyrouter`、`new-api/web/src/features/keys`
> 所属里程碑：[M3 - 跑通固定 Auto 用户产品闭环](../roadmap.md#m3)
> 当前状态：进行中
> 最近更新时间：2026-09-06
> 架构依据：[用户数据服务](../架构设计.md#812-用户数据服务)、[用户请求与用户页面](../架构设计.md#21-用户请求与用户页面)、[稳定价格](../架构设计.md#19-稳定价格架构)、[信息可见范围](../需求设计.md#17-信息可见范围)

## 1. 职责与边界

本模块负责：

- 从最近确认的站点线路、已核对价格和最新有效观测生成不可变产品快照。
- 按模型展示开放的供应商专属入口和五种固定 Auto。
- 提供可用供应商数量、SLA、延迟区间、质量等级、可信度和统计时间。
- 为每个 New API 站点提供只能读取本站产品数据的访问令牌。
- 由 New API 服务端代理请求，沿用 New API 当前登录状态和用户可用分组。
- 在 New API 页面使用其自身计费数据计算用户实际可见价格。
- 确保 ManyRouter 页面故障不影响模型调用、额度检查、转发和计费。

M3 不提供用户个人用量趋势、自定义 Auto、供应商余额、内部评分公式、检测题目或运营操作。个人统计和用户策略后续单独设计。

## 2. 系统结构与数据流

```text
最近确认线路 + 已核对价格 + M2 分组流量与质量证据
    -> 生成站点产品快照
    -> 站点只读接口
    -> New API 登录用户代理
    -> 按当前用户可用分组过滤
    -> 合并 New API 当前计费数据
    -> 模型与 Auto 页面
```

浏览器只请求同源 New API。站点访问令牌和 ManyRouter 地址仅存在于 New API 服务端，用户浏览器不会得到这些配置。

## 3. 站点身份与权限

- ManyRouter 为每个站点生成高强度随机访问令牌，只显示一次，数据库只保存摘要。
- 一个令牌只映射一个站点，只允许读取当前站产品快照，不能调用运营接口或读取其他站点。
- New API 通过服务端配置保存 ManyRouter 地址和站点令牌，所有请求必须使用 HTTPS 或受保护内网。
- 令牌支持轮换；新旧令牌短暂并存，确认 New API 已使用新令牌后撤销旧令牌。
- New API 服务端请求使用 4 秒总超时、3 秒响应头超时和 2 MiB 响应上限，不复用运营账号、站点管理令牌或供应商密钥。
- M3 产品数据不接收用户编号。New API 根据本地登录用户与可用分组自行过滤，避免跨系统传递不必要的个人信息。

## 4. 产品快照

### 4.1 生成时机

M3 首期在站点令牌读取产品时，从下列已确认数据生成快照：

- 最近完成最终核对的线路。
- 该线路引用且已经实际核对的价格版本。
- 最新成功的完整评分批次，以及近 24 小时真实分组流量。
- 线路中的专属入口和 Auto 入口开放状态。

相同内容按摘要复用上一版本，不会因页面重复刷新产生重复快照；内容变化时生成递增版本。待同步、失败或结果未知的线路不能提前进入用户数据。事件触发的预生成和跨进程缓存留到真实流量证明有需要后再增加。

### 4.2 对外字段

每份快照包含：

- 数据合同版本、快照版本、生成时间和观测截止时间。
- 模型名称。
- 开放的固定 Auto 类型、展示名称和分组标识。
- 当前确认成员数，以及是否具备至少两条可切换线路。
- 近 24 小时 SLA、首字中位数与高位区间、样本量和数据状态。
- 当前成员的质量等级、真实性状态和可信度。
- 当前价格版本与核对时间；完整用户价格由 New API 按本地计费规则计算。
- 数据不足、正在观察、近期异常、入口关闭或数据过期等用户可理解状态。

供应商内部编号、内部名称、采购价格、余额、详细错误、评分权重、门槛和检测证据不会写入用户快照。

## 5. 指标口径

- 可用供应商数量来自最近确认线路中实际启用、支持目标模型且属于该 Auto 的不同供应商记录。
- SLA 和延迟优先使用请求分组等于该 Auto 的真实流量，主动探测不计入用户 SLA。
- 没有足够 Auto 实际流量时显示数据不足，不把成员单独表现伪装成该 Auto 的真实历史表现。
- 质量使用当前成员仍在有效期内的能力测评；任一成员缺少必要证据时降低整体可信度。
- 真实性必须全部通过当前硬门槛；存在不一致成员时该成员不能出现在确认产品快照中。
- 统计时间同时展示事实截止时间和页面读取时间，避免旧数据看起来像实时数据。

## 6. 价格一致性

ManyRouter 已保存和核对 Auto 分组倍率及当时的计费依据，但完整扣费仍由 New API 的模型基础价、输入输出规则、缓存或多模态规则、用户组覆盖和额度换算共同决定。

因此：

1. ManyRouter 产品接口返回已确认的 Auto 分组、价格版本和核对时间。
2. New API 服务端先按当前用户可用分组过滤产品。
3. 页面复用 New API 现有定价接口和展示工具，选择对应 Auto 分组计算当前用户价格。
4. 找不到完整计费条目、版本不匹配或价格仍待核对时，页面显示价格暂不可确认，不自行估算。

## 7. New API 接入

### 7.1 服务端代理

New API 新增登录用户接口。处理顺序为：

1. 使用现有用户会话完成登录检查。
2. 读取本地 ManyRouter 服务端配置。
3. 以站点令牌请求 ManyRouter 产品快照，设置短超时和响应大小上限。
4. 根据当前用户可用分组过滤专属入口和固定 Auto。
5. 返回固定版本的数据合同，不返回站点令牌或上游错误正文。

ManyRouter 不可用时返回独立的产品数据暂不可用结果。该失败不会进入模型转发路径，也不会改变渠道缓存。

### 7.2 用户页面

New API 用户导航增加“模型与 Auto”页面，沿用现有设计系统、组件、响应式断点和国际化方式。

页面采用紧凑产品列表，每一行对应一个模型与一个可用产品组合：

- 顶部提供模型搜索和 Auto 类型筛选。
- 每个模型展示当前价格、可用线路数、SLA、首字区间、质量、可信度和更新时间。
- 固定 Auto 与开放专属入口直接并列，便于比较同一模型的不同产品。
- 可用 Auto 提供创建 API Key 命令，进入现有密钥流程并预选对应分组。
- 桌面使用可比较的数据表；移动端保留主要状态和操作，详细列在横向滚动区域。

页面覆盖加载、空数据、无权限、数据不足、数据过期和服务暂不可用。界面只展示当前任务需要的信息，不显示实现细节、版本规划或内部错误。

## 8. 接口合同

ManyRouter 使用独立用户数据合同，避免把运营接口和站点接口混在同一权限范围。首期只需要：

- 读取当前站点产品快照。
- 读取当前合同能力和版本，用于部署诊断和兼容检查。

产品响应携带内容摘要并支持条件请求；New API 代理会在每次读取时校验产品响应里的合同版本。单份响应设置明确大小上限；模型按名称稳定排序，Auto 按固定类型排序，确保缓存和页面结果稳定。登录用户代理响应禁止浏览器持久缓存，避免切换账号后复用前一账号的分组结果。

## 9. 验证方式

- 权限测试覆盖缺失、错误、撤销及跨站令牌，确认运营接口始终不可访问。
- 数据测试覆盖最近确认线路、待同步线路、入口关闭、价格待核对、数据不足和过期统计。
- 隐私测试确认响应不包含供应商密钥、余额、内部名称、采购价格、评分公式和检测题目。
- New API 合同测试覆盖登录、用户可用分组过滤、超时、响应过大、错误清洗和 ManyRouter 不可用。
- 价格测试把页面显示结果与同一用户、模型和 Auto 的 New API 当前计费数据逐项比较。
- 页面通过桌面与移动截图检查加载、空状态、错误、长模型名、窄屏和创建密钥入口。
- 双站真实验收确认两个 New API 实例只看到各自产品，线路变化后页面更新且价格保持一致。

截至 2026-09-06 已完成的验证：

- 领域、应用、HTTP 和 PostgreSQL 17.6 集成测试覆盖确认线路取数、价格状态、Auto 实际流量、质量汇总、令牌创建与撤销、跨站隔离及敏感字段排除。
- New API 服务端测试覆盖服务端令牌、合同校验、上游错误清洗和当前登录用户可用分组过滤。
- 密钥交互测试确认从产品页进入创建流程后，目标分组已预选且表单可以正常提交。
- 七种语言同步报告均为 0 缺失、0 多余、0 未翻译；严格类型检查、409 条前端测试和生产构建通过；本次涉及文件的 lint 通过。
- Impeccable 对用户产品页和密钥预选相关文件的静态检测没有发现问题。

仍需在两个独立 New API 实例上完成真实页面、当前计费显示、账号分组隔离和线路变化后的刷新验收。

## 10. 当前实现

截至 2026-09-06，站点只读令牌、摘要存储与撤销、最近确认线路产品快照、独立 OpenAPI 合同、New API 服务端代理、登录用户分组过滤、“模型与 Auto”页面、当前计费合并和创建密钥分组预选均已实现。页面展示价格、可用供应商数量、故障切换状态、近 24 小时 SLA、首字 P50/P95、质量、可信度和事实更新时间，并覆盖加载、空结果、数据过期及服务不可用状态。

当前代码和自动化验证已经完成，M3 仍为进行中，等待双站真实用户页面验收。
