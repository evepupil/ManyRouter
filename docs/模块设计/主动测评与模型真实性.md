# 主动测评与模型真实性模块设计

> 模块定位：在真实流量不足或线路异常时执行低频探测，并为供应商模型形成可解释的真实性与质量证据
> 对应代码：`internal/domain/evaluation`、`internal/application/evaluation`、`internal/adapters/supplier/openai`、`internal/adapters/storage/postgres/evaluation.go`、`internal/jobs/evaluation.go`、`db/query/evaluation.sql`
> 所属里程碑：[M2 - 建立可信观测与影子评分](../roadmap.md#m2)
> 当前状态：进行中
> 最近更新时间：2026-09-06
> 架构依据：[外部适配边界](../技术设计.md#53-外部适配边界)、[主动测评架构](../架构设计.md#16-主动测评架构)、[评分与状态](../架构设计.md#17-评分与状态架构)、[安全与隐私](../架构设计.md#26-安全与隐私)

## 1. 职责与边界

本模块负责：

- 为新供应商、新模型、冷门线路、异常线路和恢复候选安排低频测评。
- 分别执行供应商直连和站点链路测评，帮助定位供应商问题与站点问题。
- 检查凭证、余额、连通性、限流、首字时间、总耗时和流式完整性。
- 通过多类检测形成模型真实性结论、质量得分、可信度和最近检查时间。
- 将主动测评结果写成带独立来源的测量事实，供[窗口统计与影子评分](./窗口统计与影子评分.md)读取。
- 控制调用预算、并发、冷却期、随机抖动和失败退避。

本模块不替代真实流量统计，不把主动请求计入用户请求量，不向普通用户或供应商公开题目、参考答案和具体判断方法。M2 只记录结论并生成影子排除建议，不直接停用真实线路或修改 Auto 成员。

## 2. 结构与数据流

### 2.1 代码结构

| 位置 | 职责 |
|---|---|
| `internal/application/evaluation/` | 选择目标、安排测评、组合证据和生成结论 |
| `internal/domain/evaluation/` | 模型指纹、统计比较、真实性四态与阈值规则 |
| `internal/adapters/supplier/openai/` | OpenAI 兼容供应商直连探测 |
| `internal/domain/measurement/` | 主动测量事实、真实性结论和可信度规则 |
| `internal/adapters/storage/postgres/evaluation.go` | 测评计划、预算、样本、证据摘要和结论历史 |
| `internal/jobs/evaluation.go` | 周期任务、运行恢复和队列并发控制 |
| `db/query/evaluation.sql` | 目标、运行、样本、可信参考和结论查询 |

检测器通过统一接口返回结构化证据。更换检测方法时，调度、存储、评分和供应商适配无需随之改写。

### 2.2 数据流

```text
准入、低样本、异常或恢复触发
    -> 检查冷却期、预算和当前运行任务
    -> 生成私有测评计划与随机变体
    -> 供应商直连 / 指定站点链路执行
    -> 记录延迟、状态、用量和流式终止
    -> 提取模型指纹及质量证据
    -> 与可信参考和历史基线比较
    -> 追加测评事实与真实性结论
    -> 交给窗口统计和影子评分
```

同一目标同一时刻只允许一个有效任务。执行前持久化测评意图和预算占用，外部结果不明确时进入待核对，不能直接重复付费调用。

## 3. 测评类型与调度

### 3.1 触发条件

- 新供应商或新模型首次准入。
- 最近窗口内真实有效样本不足。
- 长时间没有真实流量。
- 供应商退出 Auto 后进入恢复观察。
- 连续失败、限流突增、延迟突变或模型回显异常后复查。
- 运营人员携带原因手动触发。

正常周期采用随机抖动，避免所有供应商在同一时间收到固定模式请求。失败后指数退避；凭证无效、余额耗尽和明确模型不一致会进入人工核对或恢复计划，不持续高频重试。

### 3.2 四类测评

| 类型 | 调用路径 | 主要用途 |
|---|---|---|
| 供应商直连 | ManyRouter 到供应商 | 检查共享凭证、余额、模型和供应商自身表现 |
| 站点链路 | ManyRouter 经指定 New API 站点 | 检查渠道配置、站点网络和完整用户路径 |
| 模型真实性 | 直连与站点链路按计划组合 | 判断声明模型与可信参考是否一致 |
| 恢复测评 | 对异常或退出对象连续复查 | 判断故障是否稳定恢复 |

直连正常而站点链路失败时，结论只影响对应站点。多个站点和直连都失败时，才支持供应商全局异常判断。

### 3.3 预算与隔离

每个供应商、模型、站点和自然日分别限制请求数、最大用量和金额。质量题与真实性统计可以消耗较多请求，必须先通过轻量探测，且不能挤占真实用户并发。

主动请求使用独立标识和专用 API Key。采集模块据此标记 `direct_probe` 或 `site_probe`，用户用量、收入和真实 SLA 统计全部排除这些请求。

## 4. 模型真实性与质量

### 4.1 分层证据

真实性判断按成本从低到高执行：

1. **协议与结构证据**：检查响应模型字段、分词计数、错误文案、响应结构和能力特征。它可以识别明显代理、协议栈或模型家族差异。
2. **统计指纹证据**：向受测模型与可信参考发送随机化的一词回答任务，比较答案分布及分半稳定性。
3. **业务能力证据**：异常、准入或恢复阶段使用真实业务题集重复比较能力差异和稳定性。

协议字段可以伪造，单道题也容易偶然命中，因此两者都不能单独证明具体模型身份。没有可信官方或自有参考账号时，只能形成“家族相似”或“两个入口疑似相同”的证据。

### 4.2 结论

模型真实性只使用以下结论：

| 结论 | 含义 | M2 影子处理 |
|---|---|---|
| 一致 | 多类证据与可信参考一致，达到样本和稳定性要求 | 可以进入后续评分 |
| 可疑 | 存在冲突或偏差，证据尚未达到排除线 | 降低可信度并安排复测 |
| 不一致 | 多次复测仍与可信参考显著冲突 | 生成硬性排除建议 |
| 证据不足 | 缺少可信参考、样本、覆盖或有效响应 | 不宣称具体模型真实，继续观察 |

每个结论保存供应商、模型、直连或站点范围、参考来源、检测套件版本、样本量、稳定性、可信度、生成时间和有效期。新结果追加保存，旧结论不能原地改写。

真实性结论的主体固定为“供应商 + 对外模型”。站点身份只标明证据来自哪条链路；单个站点的网络或配置失败只能形成站点局部问题，不能改写供应商全局真实性。

只有存在未过期的官方参考或运营人员确认的可信参考，并且受测结果与参考结果满足同一协议，才允许得出“一致”。没有可信参考时仍采集自身稳定性、服务栈线索和供应商间指纹碰撞，但结论保持“证据不足”，可附带模型家族提示或疑似共用后端提示。

### 4.3 首期统计指纹协议

首期 `single_token_jsd_v1` 采用以下固定协议，所有参数和阈值随算法版本保存：

- 四类一词回答题型，中文和英文各一组，共 8 个样本单元。
- 每个样本单元至少 10 个有效结果，计划采集 12 次，为偶发失败留出余量；完整一轮计划调用 96 次。
- 生成参数固定为 `temperature=1`、`top_p=1`、`max_tokens=16`，受测入口和可信参考保持一致。
- 使用以 2 为底的 Jensen-Shannon 距离，并做分半稳定性检查。
- 距离不高于 0.25 视为一致候选，0.25 至 0.35 视为可疑，高于 0.35 视为不一致候选。
- 单轮高于 0.35 只记录“可疑”；更换随机种子复测仍高于 0.35，且其他证据没有解释冲突时，才允许记录“不一致”。

429、超时、拒答、参数不兼容和样本不足属于测评失败或证据不足，不能计作模型不一致。首轮阈值来自开源论文与实现，需要在可信参考集和已知不同模型集上校准后才能用于硬性排除建议。

### 4.4 质量得分

质量与真实性分开。真实性回答“是否符合声明”，质量回答“完成目标任务的表现”。质量题按能力类别保存通过率、评分分布和波动，并记录题集版本与参考版本。

首期题集只覆盖当前实际销售模型需要的能力。题目、参考答案和判定细节放在受限检测资产中；业务数据库保存题目编号、版本、结构化结果和摘要。M2 默认不长期保存完整提示词与模型原文。

### 4.5 防针对性规避

- 测试套件私有保存，外部接口只返回等级、可信度范围和更新时间。
- 同一能力准备多组等价题，随机改写、随机顺序并跨时段复测。
- 参考账号、受测账号和站点链路使用相同参数及可比环境。
- 检测方法升级时增加版本，历史结论保留原方法和阈值。
- 发现供应商针对固定题目返回特制答案时，记录重大风险并转人工处理。

## 5. 开源调研结论

### 5.1 首期可参考

| 方案 | 许可证与活跃度 | 适合借鉴的内容 | 限制 |
|---|---|---|---|
| [`modelprint`](https://github.com/unclecode/modelprint) | MIT；2026-09-05 仍活跃 | 分词计数、错误文案、响应结构等廉价探针 | 更适合识别模型家族或服务栈，字段可被伪造 |
| [`llm-fingerprint-detector`](https://github.com/ToseaAI/llm-fingerprint-detector) / [One Token 论文](https://arxiv.org/abs/2607.10252) | MIT；项目较新 | 一词回答分布、Jensen-Shannon 距离和分半稳定性 | 约需 100 至 400 次请求；论文在 40 组比较中的等错误率仍为 7.3%，必须使用可信参考并保留不确定结论 |
| [`model-equality-testing`](https://github.com/irenasaracay/model-equality-testing) | 仓库许可证声明不完整 | 异常后用真实业务题多次比较；论文报告平均每题 10 个样本时检出能力为 77.4% | 适合复核，不能作为单独硬门槛；只参考论文方法并自行实现 |

首期优先独立实现廉价结构探针和 One Token 的统计方法，不直接引入年轻 npm 包。业务题比较作为准入、异常和恢复阶段的第二层证据。

### 5.2 首期暂不采用

- `LLMmap` 使用较重的 PyTorch 运行环境且模板较旧，只保留研究参考。
- `TRAP`、`ZeroPrint` 需要模型权重或 GPU。
- `TOPLOC`、`SVIP` 需要供应商返回中间激活信息。
- `MarkLLM`、`SynthID` 依赖模型提供方预先植入水印。

这些方案与当前黑盒 API 场景、部署成本或供应商配合条件不匹配，不进入 M2 首期依赖。

### 5.3 sub2api 主动监控

[`sub2api` 主动监控](https://github.com/Wei-Shaw/sub2api/blob/ab99d56e9626e6cd731592dae8553c9758a0efa2/backend/internal/service/channel_monitor_checker.go#L55-L119)提供按供应商协议构造请求、随机算术挑战、定时间隔、抖动和历史状态，可参考其轻量连通检查与调度方式。

它的旧版主动探测与新版被动统计采用互斥模式，历史主要记录总耗时、网络探测耗时和状态。ManyRouter 需要主动测评与真实流量同时工作，并额外记录首字、用量、流式完成、可信参考和模型证据，因此不直接依赖该实现。

## 6. 关键决策

1. 主动数据与真实流量共享测量结构，但始终保留来源并分别统计。
2. 直连和站点链路分别执行，避免将站点配置故障误判为供应商全局故障。
3. 模型真实性采用多层证据和四态结论，不用单个响应字段或单道题直接判定。
4. 无可信参考时不输出“具体模型已验证”的结论。
5. 测评题目与判定细节保持私有，数据库默认只保存版本和结构化证据。
6. 外部调用前持久化意图和预算，结果不明确时先核对再重试。

## 7. 当前实现

截至 2026-09-06，M2 已实现测评申请、周期调度、River 执行、供应商凭证解密、OpenAI 兼容探针、样本持久化、真实性指纹/结论、能力质量评估和可信参考管理。健康测评每 6 小时执行，质量测评每 7 天执行；存在其他供应商可信参考时，真实性测评每 7 天执行。每个目标同一用途只保留一个未完成任务，未入队和超时运行会重投原运行；瞬时执行错误按重试时间恢复。

真实性首期固定 `single_token_jsd_v1`：8 个中英文样本单元，每单元计划 12 次，完整一轮 96 次，固定温度、top-p 和最大输出，并做分半稳定性与响应模型冲突检查。质量题只保存结构化结果和摘要。外部调用前先预留样本与预算，按请求编号和请求摘要幂等，单日默认上限 200；进程在付费调用后中断时，占位样本保留为待核对，该轮终止且不会自动重复调用。主动请求以 `direct_probe` 写入事实，不进入真实用户请求量、收入和 SLA。

当前接口只开放供应商直连测评；站点链路请求会明确拒绝，因为 M2 尚未设计和保存站点链路专用用户密钥，也未完成其权限与真实验证。M1 三个供应商记录共用一个真实上游，也不能作为真实性或厂商差异的可信参考。当前仍缺少可用于生产判断的真实主动测评样本、可信参考账号和两站链路验证。

## 8. 验证方式

当前验证方式：

- 领域测试：触发条件、冷却期、预算占用、四态结论、有效期和证据不足处理。
- 调度测试：并发领取、随机抖动、失败退避、进程恢复和不明外部结果核对。
- 检测器测试：固定样本验证结构探针、统计距离、分半稳定性和阈值边界。
- 适配测试：直连覆盖成功、限流、超时、截断流和密钥清洗；站点链路实现后再验证两条路径使用一致参数。
- 安全测试：普通接口无法获得题目、参考答案、供应商密钥和完整响应。
- 自动化覆盖测评调度、冷却/质量周期、失败恢复、96 次计划、预算占位、样本幂等、可信参考修订和四态结论；重点测试见 `internal/application/evaluation/*_test.go` 与 `m2_evaluation_idempotency_integration_test.go`。
- 真实验收仍待完成：可信参考与受测入口的多时段盲测、真实成本和误判报告，以及故意使用不同模型验证“不一致”路径。
- 隔离验收：主动请求不进入真实用户请求量、收入和真实 SLA。

模型真实性通过需要同时给出参考来源、检测版本、样本量、稳定性和复测结果。当前只能证明协议、状态机和存储边界已实现，不能把自动化探针结果当作已完成的真实可信参考验收。

## 9. 待扩展项

- 更多模型家族、语言和工具调用题集。
- 多地区执行节点与网络基线。
- 供应商配合的水印或签名证明。
- 更长周期的漂移检测和题集自动轮换。
- 完整响应的受限短期诊断存储与人工复核台。
