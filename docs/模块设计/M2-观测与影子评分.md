# M2 观测与影子评分

> 模块定位：采集 New API 站点的真实请求事实和低频主动测评结果，形成可追溯的统计、模型真实性结论、质量结论与评分建议。

> 技术依据：[技术设计](../技术设计.md)

## 1. 职责与边界

### 1.1 负责内容

- 从每个受管 New API 站点的独立日志库读取统计所需的请求事实。
- 通过只读、最小字段、版本化日志视图获取数据，按站点保存独立采集进度。
- 处理迟到记录、重复记录和 New API 重试产生的多次上游尝试。
- 区分真实用户流量与主动测评流量。
- 汇总站点、供应商、供应商模型和时间窗口维度的表现。
- 执行供应商连通性、模型真实性、模型质量和恢复相关的低频主动测评。
- 形成供应商全局、供应商模型和站点局部的观测结论。
- 生成带规则版本和统计依据的影子评分与线路调整建议。
- 向运营控制台提供数据新鲜度、样本情况、测评结果、评分解释和建议历史。

### 1.2 不负责内容

- 不直接修改 New API 业务主库、日志库或缓存。
- 不直接创建或修改渠道、分组、倍率、Auto 成员和渠道状态。
- 不在用户请求过程中同步调用 ManyRouter，也不参与用户请求选路。
- 不把主动测评计入用户真实请求量、用户体验统计或站点收入统计。
- 不在本里程碑自动应用线路建议；真实线路继续由 M1 的人工运营流程维护，M3 才进入自动调整。
- 不向普通用户公开检测题目、内部判定细节、供应商凭证、采购成本或完整评分规则。

## 2. 结构与数据流

```text
New API 用户请求
        │
        ▼
站点独立日志库的版本化只读视图
        │ 站点游标增量读取
        ▼
ManyRouter 观测采集
        │ 标准化、去重、重试归并
        ▼
追加保存的测量事实
        ├──────────────┐
        ▼              ▼
真实流量统计       主动测评结果
        └──────┬───────┘
               ▼
样本检查、硬性排除、评分建议
               ▼
影子评分与线路调整建议
               ▼
运营控制台查看与人工决策
```

### 2.1 请求事实采集

- 每个站点使用独立采集进度，按稳定顺序读取日志。
- ManyRouter 成功保存一批事实后才推进对应游标。
- 重复执行同一批读取不会产生重复事实。
- 迟到或补写记录通过回看范围补采，不把暂时未读到的数据当作零请求。
- 日志库无法直连时，可以使用 New API 的 HTTP 日志能力作为兼容回退，但不得改变统一观测结果的含义。

### 2.2 请求归并

一次用户请求可能包含多次上游尝试。观测结果需要同时保留：

- 用户请求最终是否成功。
- 每次上游尝试使用的站点、供应商、模型、耗时和错误分类。
- 最终完成请求的实际渠道。

供应商表现使用上游尝试事实计算，用户体验使用最终请求结果计算，两种口径分别展示。

### 2.3 主动测评

主动测评覆盖供应商连通性、余额和模型可用性、模型真实性与质量，以及退出后的恢复检查。测评结果单独标记来源、时间和适用范围，供评分使用，但不进入用户流量统计。

## 3. 关键决策

### 3.1 观测入口

高频统计优先读取 New API 独立日志库的版本化只读视图。New API 适配仓库需要补充统一的毫秒级请求总耗时，并提供可验证的视图版本；这项改动只补充观测事实，不改变用户请求处理结果。

ManyRouter 禁止连接 New API 业务主库和直接改写 New API 数据。日志只读账号只能获得统计所需内容，不能读取请求正文、响应正文、用户身份细节、密钥等排除信息。

### 3.2 影子评分

影子评分只产生建议，不改变真实线路。建议需要说明统计时间范围、样本是否充足、采用的规则版本、硬性排除原因和建议影响范围，供 M3 的自动运营流程使用。

评分结论分开表示供应商全局状态、供应商模型状态和站点局部状态。全局严重问题可以形成全局停用建议，站点网络或配置问题只形成对应站点的建议。

### 3.3 数据与历史

- 原始测量事实、主动测评结果、统计结果和影子评分快照都保留历史。
- 当前结论与历史结论分开查看。
- 评分规则变化生成新的规则版本，不覆盖旧结论。
- 数据不足、数据过期或日志来源异常时，明确标记结论不可用，并冻结扩张或恢复建议。
- 评分中使用的价格、延迟、SLA 和质量四个维度保持可解释，具体公式和参数进入后续模块设计确认。

## 4. 当前实现

- ManyRouter 尚未创建运行代码，本模块当前只有需求、技术和架构依据。
- `new-api` 目录是已分析的 New API 源码基线，不代表 ManyRouter 与其已经完成运行兼容。
- 毫秒级请求总耗时和版本化日志只读视图尚未完成适配与验证。
- 采集游标、事实归并、统计、主动测评和影子评分尚未实现。
- 当前没有可宣称完成的真实日志采集、主动测评或评分结果。

## 5. 验证方式

### 5.1 逻辑验证

- 用确定性样例验证真实流量与主动测评的来源区分。
- 验证重复批次、迟到记录、采集游标恢复和重试归并不会造成漏记或重复计算。
- 验证站点、供应商、供应商模型和时间窗口之间的统计范围隔离。
- 验证样本不足、数据过期、凭证失效、余额耗尽和模型真实性失败能够形成明确结论。
- 验证影子评分只产生建议，绝不调用线路写入能力。

### 5.2 集成验证

- 使用真实 New API 进程和独立日志库验证版本化视图、字段最小化、稳定排序、毫秒级总耗时和只读权限。
- 验证 ManyRouter 中断或日志库暂时不可用时，New API 用户请求继续运行，采集进度不会错误推进。
- 让同一站点产生包含重试的真实请求，核对最终请求统计与上游尝试统计的区别。
- 验证主动测评结果可查询，且不会进入用户真实流量和收入统计。

### 5.3 M2 退出标准

- 日志增量采集与 New API 数据抽样一致，并可断点续传。
- 主动测评、模型真实性和质量结果可查，来源与时间清楚。
- 统计和评分建议可以解释其依据与适用范围。
- 影子评分不会自动修改真实线路、价格或渠道状态。

## 6. 待扩展项

- 更多地区的主动测评和地区化结论。
- 更丰富的模型能力检测与质量指标。
- 用户自定义 Auto 所需的策略快照和用户级报价输入。
- 面向其他网关的观测适配器。
- 更大规模日志保留、归档和报表能力。

以上能力不改变 M2 的影子评分边界，新增后仍需保留来源、规则版本和历史可追溯性。
