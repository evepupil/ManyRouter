# 运营账号与权限模块设计

> 模块定位：为运营控制台提供所有者初始化、登录、会话与写操作保护，并保留部署脚本的管理凭证接入
> 对应代码：`internal/application/auth`、`internal/adapters/storage/postgres/auth.go`、`internal/transport/http/auth.go`、`internal/transport/http/router.go`、`db/query/auth.sql`
> 所属里程碑：[M1 - 跑通多站人工运营闭环](../roadmap.md#m1)
> 当前状态：进行中
> 最近更新时间：2026-09-05
> 架构依据：[内部分层](../架构设计.md#7-manyrouter-内部分层)、[身份审计与通知](../架构设计.md#813-身份审计与通知)、[密钥与身份](../架构设计.md#263-密钥与身份)

## 1. 职责与边界

- 初始化唯一所有者，提供登录、退出和当前登录状态查询。
- 检查浏览器会话、账号启用状态和所有者权限。
- 对浏览器写操作核对请求来源和防伪造令牌。
- 持久保存登录尝试次数，限制密码猜测；记录成功初始化、登录和退出。
- 继续支持现有部署管理令牌，以兼容运维脚本。

M1 只开放所有者，不提供公开注册、账号列表、邀请、密码找回或第三方登录。管理员与只读角色留待后续扩展；当前服务端对非所有者角色拒绝运营访问。New API 的普通用户与 API Key 继续由 New API 管理。

## 2. 结构与数据流

| 层次与位置 | 职责 |
|---|---|
| `internal/application/auth` | 初始化、密码验证、随机会话、防伪造令牌和限流规则 |
| `internal/adapters/storage/postgres/auth.go` | 首次初始化事务、会话、限流持久化与成功操作审计 |
| `internal/transport/http/auth.go` | 登录接口、Cookie、来源核对和运营身份上下文 |
| `internal/transport/http/router.go` | 在全部运营接口前统一鉴权 |

最小数据为运营账号、登录会话和登录尝试窗口。账号记录用户名、密码摘要、角色与启用状态；会话只保存会话令牌摘要、防伪造令牌摘要及过期时间。原始密码和原始会话令牌不进数据库或日志。

```text
部署令牌 + 首个账号密码
    -> 核对部署令牌
    -> 数据库互斥检查尚无账号
    -> 创建所有者和操作记录
    -> 创建浏览器会话

账号密码
    -> 检查来源和登录次数
    -> 核对密码与账号状态
    -> 创建会话，返回受保护 Cookie

浏览器运营请求
    -> 会话有效且账号为启用的所有者
    -> 写操作额外核对来源和防伪造令牌
    -> 将真实操作者交给业务接口
```

## 3. 初始化与密码规则

- 初始用户名为 3 至 80 位字母、数字、点、下划线或连字符，统一转成小写；首字符要求字母或数字。
- 密码为 12 至 128 字节，保存前使用 Argon2id 加独立随机盐计算摘要，参数为 64 MiB 内存、3 次计算、2 路并行。
- 初始化同时要求部署配置中的现有运营管理令牌，浏览器不能仅凭站点未初始化就创建所有者。
- 数据库事务使用固定初始化锁，并在持有锁后再次查询账号。两个并发初始化最多成功一次。
- 初始化完成后关闭该入口的创建能力，即使账号被停用也不能通过再次初始化绕过。
- 不存在的账号与错误密码返回相同提示，并执行相同密码计算，减少通过耗时判断账号是否存在的机会。
- 每个进程最多同时执行两份高成本密码计算，额外请求等待空位或随请求取消，避免并发登录占用过多内存。

## 4. 会话与权限规则

- 每次登录生成 32 字节随机会话令牌；数据库只保存 SHA-256 摘要。
- 会话固定 12 小时过期，服务端每次请求查询有效期和当前账号状态。退出删除该会话，之后旧 Cookie 无法继续访问。
- Cookie 使用 `HttpOnly`、`SameSite=Strict` 和根路径，生产默认 `Secure`。本地纯 HTTP 开发需要明确设置 `MANYROUTER_AUTH_COOKIE_SECURE=false`，生产保持 `true`，不能根据客户端头自动降级。
- `/session` 返回当前用户和防伪造令牌，不返回原始会话令牌。防伪造令牌从随机会话密钥派生，可在刷新页面后重建；数据库保存其摘要用于核对。
- 当前所有运营能力只允许所有者。角色发生变化或账号被停用后，已有会话立即失去对应权限。
- 现有部署 Bearer 令牌保留为机器接入入口，身份记为部署所有者；浏览器登录使用账号身份。运营接口将身份传入业务审计。
- 静态资源、健康检查及明确列出的认证入口可匿名访问；未知 `/api` 路径也经过鉴权，不能通过另造路径绕过。

## 5. 请求保护与限流

- 初始化和登录只接收 JSON。浏览器写操作核对 `Origin` 的站点与协议，并拒绝跨站或同站不同源的 Fetch 请求。
- 会话授权的运营写操作及退出需要 `X-CSRF-Token`。该令牌用于证明请求来自已读取本站登录状态的页面。
- 请求头无浏览器来源信息时仍要求会话防伪造令牌；部署 Bearer 调用独立验证部署凭证。
- 每个网络来源 15 分钟最多允许 30 次初始化或登录尝试；每个用户名 15 分钟最多允许 10 次登录尝试。计数保存在数据库并原子递增，服务重启或并发请求不会清空限制。
- 来源采用直接连接地址，客户端自行填写的转发地址不会改变限流身份。反向代理后的多个用户可能共享来源限制；后续需要按明确可信代理配置扩展，禁止直接信任任意转发头。
- 限流键只存摘要，审计不记录密码、部署令牌、Cookie 或防伪造令牌。
- 新登录会清理过期会话，每次登录或初始化会清理过期限流窗口，避免失效记录长期增长。

## 6. 接口与相邻模块

| 方法与路径 | 业务结果 |
|---|---|
| `GET /api/v1/auth/status` | 是否已经初始化 |
| `POST /api/v1/auth/setup` | 核对部署令牌并创建首个所有者，同时登录 |
| `POST /api/v1/auth/login` | 验证账号密码并创建会话 |
| `GET /api/v1/auth/session` | 当前账号与防伪造令牌 |
| `POST /api/v1/auth/logout` | 撤销当前会话并清理 Cookie |

[运营控制台](./运营控制台.md)负责初始化、登录页和过期后的导航；[站点与供应商接入](./站点与供应商接入.md)、[人工策略管理](./人工策略管理.md)与[稳定价格管理](./稳定价格管理.md)复用统一运营鉴权，不各自实现登录逻辑。

## 7. 关键决策

1. 复用现有 PostgreSQL 保存账号、会话和限流记录，避免增加新的认证服务。
2. 使用服务端会话，使退出、账号停用和角色调整可以即时生效。
3. 一次性初始化同时依赖部署令牌和数据库互斥检查。
4. 默认安全 Cookie、来源核对和防伪造令牌共同保护浏览器写操作。
5. 成功认证审计与会话变更同事务提交；失败尝试写入限流记录，不记录敏感输入。

## 8. 当前实现

已实现认证用例、Argon2id 密码摘要、会话过期与撤销、所有者权限、持久限流契约、HTTP 接口及来源和防伪造令牌核对。PostgreSQL 实现、SQL 查询、M1 数据迁移与服务启动入口已接入；旧运营接口也记录当前真实操作者。[运营接口契约](../../api/operations.yaml)覆盖认证和 M1 运营操作。

认证核心与 HTTP 测试已通过，覆盖会话生命周期、权限、持久限流契约、来源和防伪造检查。独立 PostgreSQL 数据范围验证了并发初始化、会话与审计持久化、退出撤销及限流原子累加；Windows Edge 已验证初始化或登录、会话访问与退出后拒绝，完整项目门禁已经通过。

## 9. 验证方式

- 核心单测：首次初始化、错误令牌、账号密码限制、重复初始化、错误密码、未知账号、过期与撤销、账号停用、非所有者角色、重启后限流窗口保留。
- HTTP 测试：同源登录、跨源拒绝、Cookie 标记、遗漏防伪造令牌拒绝、会话恢复、退出后拒绝、未知 API 鉴权和原有 Bearer 调用兼容。
- PostgreSQL 集成：并发初始化仅成功一次、会话及审计提交、退出撤销、限流窗口原子递增。
- 控制台验收：初始化后登录、刷新保持状态、退出、会话过期后返回登录，以及直接调用运营接口无法绕过身份核对。
