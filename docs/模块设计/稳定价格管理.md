# 稳定价格管理模块设计

> 模块定位：按站点保存专属分组及固定 Auto 的倍率草案、价格版本、计费配置依据和最近核对结果
> 对应代码：`internal/domain/operations`、`internal/application/operations`、`internal/adapters/storage/postgres/operations_price.go`、`internal/adapters/storage/postgres/operations_plan.go`、`internal/adapters/gateway/newapi/billing.go`、`internal/application/reconciliation/site_service.go`、`api/operations.yaml`
> 所属里程碑：[M1 - 跑通多站人工运营闭环](../roadmap.md#m1)
> 当前状态：进行中
> 最近更新时间：2026-09-05
> 架构依据：[内部分层](../架构设计.md#7-manyrouter-内部分层)、[稳定价格](../架构设计.md#88-稳定价格)、[稳定价格架构](../架构设计.md#19-稳定价格架构)、[一致性模型](../架构设计.md#23-一致性模型)

## 1. 职责与边界

- 分别保存每个站点的供应商专属分组和固定 Auto 倍率。
- 由运营人员创建价格草案、确认发布，并保留每个分组独立的价格历史。
- 读取站点计费配置和 New API 版本，保存本次价格使用的配置依据与摘要。
- 将发布价格交给[单站线路方案](./单站线路方案.md)，经同步和重读后记录成功核对时间。
- 区分计划采用的价格、历史确认记录和仍待核对的外部实际状态。

M1 已实现倍率草案及配置一致性核对，尚未实现逐模型销售金额计算、特殊计费公式或自动利润计算。采购价格由[站点与供应商接入](./站点与供应商接入.md)维护；用户扣费、额度、账单及实时请求仍由 New API 处理。

## 2. 结构与数据流

### 2.1 当前目录

| 位置 | 当前职责 |
|---|---|
| `internal/domain/operations/types.go`、`validation.go` | 价格输入、版本和十进制倍率规则 |
| `internal/application/operations/service.go`、`prepare.go` | 草案与发布入口、读取目标站点计费配置 |
| `internal/adapters/storage/postgres/operations_price.go` | 新价格版本、最新草案检查、发布状态与专属组倍率更新 |
| `internal/adapters/storage/postgres/operations_transaction.go`、`operations_plan.go` | 事务、线路引用、任务和审计 |
| `internal/adapters/storage/postgres/operations_read.go` | 历史价格及最近确认记录查询 |
| `internal/adapters/gateway/newapi/billing.go` | 从 New API 读取计费配置并生成稳定摘要 |
| `internal/application/reconciliation/site_service.go`、`internal/adapters/storage/postgres/reconciliation_site.go` | 写入前后核对，记录价格确认结果 |
| `internal/transport/http/operations*.go`、`api/operations.yaml` | 运营接口与必填字段检查 |

当前与其他人工运营用例共用应用入口，存储与同步按职责分文件；没有独立报价服务或实时计费服务。

### 2.2 保存内容

| 内容 | 当前含义 |
|---|---|
| 定价对象 | 站点和稳定分组名，专属组与 Auto 各有独立版本序列 |
| 价格版本 | 倍率、原因、版本、状态、创建时间，以及计费配置快照与摘要 |
| 发布记录 | 人工确认发布的时间，进入后续线路同步 |
| 核对记录 | 最近一次成功核对时间及当时线路引用 |
| 线路引用 | 完整站点快照保存采用的价格版本及计费配置摘要 |

当前草案创建后也作为历史版本保存，没有原地编辑接口。需要修正时新建下一份草案；每组仅最新草案允许发布。恢复旧倍率时，可查看历史并以该倍率创建新草案，再按当前计费配置发布，尚无一键恢复历史价格接口。

### 2.3 当前流程

```text
选择站点、分组，输入倍率及原因
    -> 读取该站计费配置和 New API 版本
    -> 保存草案及独立版本，暂不安排线路变更
    -> 运营人员确认发布最新草案
    -> 再读计费配置并比较摘要
    -> 同一事务更新发布状态、线路、同步任务和审计
    -> 同步前后分别重读核对
    -> 记录核对成功时间，或保留失败及待确认状态
```

当前没有逐模型金额对比或独立价格预览接口。已有控制台展示倍率、配置依据、历史和同步结果。

## 3. 当前定价规则

### 3.1 独立价格与版本

- 同一供应商在两个站点可拥有不同倍率；不同 Auto 与专属分组分别保存价格。
- 成员调整、供应商密钥轮换和入口开关不会自动创建新的售价版本，也不会根据采购成本重算倍率。
- 初次投放时使用人工提交的倍率建立价格版本；已有 M0 专属分组首次进入完整站点线路时，会沿用原倍率补建价格记录。
- 创建草案要求分组已属于目标站点，倍率大于零、不超过 `999999.999999`，最多六位小数。
- 发布时要求草案版本一致、仍为该组最新版本，并且现场重读的计费摘要与草案一致；不满足时拒绝发布。
- 发布新版本会将此前发布或确认过的版本标为已替代，但保留其历史核对时间。新版本是否已经在外部生效，仍要等待同步结果。
- 同一请求编号在有效记录期内复用执行结果；换用新编号创建内容相同的草案仍产生新价格版本。

### 3.2 计费依据实际覆盖什么

分组倍率只表示在 New API 模型计费基础上的调整比例。实际扣费还取决于输入输出用量、模型基础价格、输出倍率、缓存或其他计费方式，以及用户组覆盖规则。只验证分组倍率不能证明完整售价正确。

当前适配器读取模型基础倍率、输出倍率、按次价格配置，并收集目标版本实际提供的缓存、图像、音频、用户组覆盖和额度换算等白名单配置。New API 版本本身也进入摘要；无关选项和密钥不进入价格证据。

读取时要求存在模型基础倍率、输出倍率和模型价格三项配置，配置必须能解析为 JSON。数值规范化后计算 SHA-256 摘要，使字段顺序或等价数字写法不制造差异。

这份依据证明的是“当时读取并核对过哪些配置”。当前没有逐模型检查价格条目是否完整，没有重现各类计费算法，也没有验证每项覆盖规则最终如何作用于真实账单。上述能力不能计入已实现的报价范围。

### 3.3 基础配置与变更边界

- 普通产品改价只更改受管分组倍率，不顺带修改全站模型基础价格，也不接管非受管分组。
- 同站当前价格引用的计费依据应保持一致。缺少依据或混用不同摘要时，线路不会被当作可以安全确认的价格配置，同步会报告需处理的偏差。
- 初始投放或沿用 M0 倍率时，站点不可达仍可能保存缺少计费依据的待同步版本；后续读取依据后补齐，核对成功前不能宣称已经确认生效。
- 发布和同步均会重新检查计费配置变化；有偏差时阻止普通激活与价格确认。紧急停用先执行安全关闭，再报告计费偏差，不应被改价问题阻挡。
- 成员带来新增模型时，当前仍沿用原分组倍率，没有单独的模型报价范围审批。运营人员需要核对该模型基础计费规则和实扣结果。

## 4. 最近确认与实际状态

价格列表包含价格状态、发布与核对时间，以及是否属于该组最近成功核对版本的标记。

- `applied_at` 是该版本首次成功核对的历史时间，普通重复核对不会改写它，也不代表从此以后外部配置始终未变。
- `is_last_confirmed` 表示本地记录中该站该组最近一次成功核对的版本。新价格已发布但未核对时，旧版本仍可带此标记，即使旧版本状态已是“已替代”。
- 新线路等待同步、发生部分写入或核对失败时，当前外部实际价格需要确认。旧版本的历史确认记录不能作为实时售价事实。
- 站点管理员直接修改基础价格、倍率或覆盖规则可能立即影响真实扣费。当前没有持续实时监听，也没有原子冻结外部修改的能力；后续重读可发现与记录不一致。

因此，价格页面使用“最近确认”表达已知事实，并结合线路和同步状态判断本次变更是否核对完成。

## 5. 同步与协作

价格与[人工策略管理](./人工策略管理.md)分别保存。线路模块汇总专属组、Auto、价格版本和计费摘要，网关适配器负责保留非受管配置并写入受管倍率。

同步先核对计费依据，写入并重读全部受管倍率，再立即复核一次计费依据。倍率和依据一致后独立记录相关价格已核对；后续渠道或入口操作失败不会抹去这次价格事实，整站线路仍保持失败并展示部分结果。一个站点的价格结果不更新其他站点记录。

New API 现有接口无法一次原子切换渠道、价格和入口开关。部分写入后失败可能已经影响实际扣费或入口权限，必须显示待确认状态；正式整批能力属于 M4。

用户已确认专属分组和固定 Auto 统一按入口开放状态管理：关闭入口会使已有绑定该组的 API Key 后续请求被拒绝。当前沿用 New API `UserUsableGroups` 接口及其权限检查，关闭后返回 403 符合业务规则。关闭保留价格版本、倍率和核对历史；重新开放沿用当前有效价格配置，不重新计算售价。

## 6. 接口

| 接口 | 当前能力 |
|---|---|
| `GET /api/v1/ops/prices` | 查询价格历史、配置依据和最近确认标记 |
| `POST /api/v1/ops/prices` | 输入站点、分组、倍率及原因，创建新草案 |
| `POST /api/v1/ops/prices/{id}/publish` | 携带草案版本，人工确认发布最新草案 |
| `GET /api/v1/ops/plans`、`GET /api/v1/ops/sync-operations` | 查看引用价格的线路和逐站核对结果 |

写操作要求重复提交编号并复用[运营账号与权限](./运营账号与权限.md)保护；[运营控制台](./运营控制台.md)展示倍率和结果。金额及倍率通过十进制字符串传输，持久化时间使用 UTC。

## 7. 关键决策

1. 价格版本与策略版本独立，成员变化不自动调价。
2. 每个站点单独保存计费依据，New API 版本变化也需要重新核对。
3. 计费配置一致性与实际账单正确性分别验证，配置摘要不替代完整报价计算。
4. 发布、线路及任务共同提交；实际结果通过外部重读确认。
5. 历史记录保留最近确认事实，不把未知的当前状态显示为已知售价。

## 8. 当前实现

已实现按站点与分组创建倍率草案、独立递增版本、最新草案发布、原因与审计、站点计费配置和 New API 版本摘要、完整线路价格引用、写入前后核对及历史确认记录。运营接口和控制台已接入。

尚未实现逐模型金额报价、特殊计费计算、自动利润、草案原地编辑、独立预览或历史价格一键恢复。实际扣费抽样及真实双站完整验收仍待完成，模块保持进行中。

## 9. 验证方式

- 规则测试：`internal/domain/operations/validation_test.go` 覆盖倍率精度与范围。
- 接口测试：`internal/transport/http/operations_test.go` 和 `operations_input_test.go` 覆盖价格字符串、必填字段、发布版本和错误响应。
- 配置依据测试：`internal/adapters/gateway/newapi/billing_test.go` 覆盖必要配置、数字规范化、New API 升级影响和敏感选项排除。
- 数据库测试：`internal/adapters/storage/postgres/operations_integration_test.go` 覆盖站点独立、价格草案发布及策略引用。
- 同步测试：`internal/application/reconciliation/site_service_test.go` 覆盖计费偏差、紧急停用、价格独立确认和后续渠道失败不确认整站。
- 待完成真实验收：两个站点分别设置倍率，按实际模型与计费类型抽样对照扣费；更换成员后倍率保持；检查新版本未核对时历史记录的展示。

## 10. 待扩展项

- 模型价格范围检查、独立预览、草案编辑及历史价格恢复快捷入口。
- 成本、利润与风险准备计算；已有采购价格目前仅供运营参考。
