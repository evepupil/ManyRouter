# New API 正式集成与兼容模块设计

> 模块定位：用每站窄权限令牌和整批接口替代正式站点上的广泛管理权限，并用能力合同判断 ManyRouter 与 New API 是否可以安全协作
> 对应代码：`internal/application/compatibility`、`internal/adapters/gateway/newapi`、`internal/adapters/storage/postgres/compatibility.go`、`internal/application/reconciliation/site_managed_sync.go`、`internal/transport/http/runtime_health.go`、`api/operations.yaml`、`new-api/controller/manyrouter_sync.go`、`new-api/controller/manyrouter_logs.go`、`new-api/service/manyrouter/sync.go`、`new-api/model/manyrouter_sync*.go`、`new-api/router/api-router.go`
> 所属里程碑：[M4 - 完成正式集成与可复制发布](../roadmap.md#m4)
> 当前状态：进行中
> 最近更新时间：2026-09-07
> 架构依据：[New API 兼容](../架构设计.md#811-new-api-兼容)、[正式同步](../架构设计.md#202-正式同步)、[一致性模型](../架构设计.md#23-一致性模型)、[架构约束](../架构设计.md#28-架构约束)

## 1. 职责与边界

本模块负责：

- 在每个 New API 实例上提供只允许 ManyRouter 同步受管资源的服务端令牌。
- 用一个整批请求提交站点期望的渠道、分组倍率和用户入口状态。
- 在 New API 内完成完整校验、数据库事务、缓存刷新、审计和最终摘要返回。
- 向 ManyRouter 返回能力合同、限制、运行版本和重试配置。
- 通过同一窄令牌向 ManyRouter 返回裁剪后的调用日志，延续 M2 统计采集。
- 在 ManyRouter 保存最近兼容检查结果，并在能力不足时停止自动写入。
- 继续保护 New API 中由管理员或其他系统维护的渠道、分组和设置。
- 保留现有逐项管理接口适配器，供旧站点迁移和回归测试使用。

本模块不转发用户模型请求，不读取用户密钥，不管理 New API 用户账号，也不替代 M2 的日志采集。用户请求仍直接进入 New API。

## 2. 结构与数据流

```text
ManyRouter 已确认线路快照
    -> 读取 New API 能力和当前受管状态
    -> 校验合同、限制、重试配置和当前状态摘要
    -> 提交整批期望状态
    -> New API 校验受管边界
    -> 数据库事务更新渠道和分组设置
    -> 刷新渠道、能力和系统设置缓存
    -> 保存审计与幂等结果
    -> 返回受管状态摘要
    -> ManyRouter 再次独立读取并核对
    -> 确认线路或保留上一版
```

### 2.1 ManyRouter 目录

| 位置 | 职责 |
|---|---|
| `internal/application/compatibility/` | 能力合同、支持判断、兼容结果和原因 |
| `internal/adapters/gateway/newapi/` | 能力读取、受管状态读取、整批应用和旧接口适配 |
| `internal/application/reconciliation/` | 优先使用整批同步，完成后重新读取核对 |
| `internal/adapters/storage/postgres/` | 保存站点能力快照、检查时间和当前兼容结论 |
| `internal/transport/http/`、`api/operations.yaml` | 兼容检查与查询接口 |

### 2.2 New API 目录

| 位置 | 职责 |
|---|---|
| `controller/manyrouter_sync.go` | 三个专用 HTTP 接口、请求大小和错误清洗 |
| `controller/manyrouter_logs.go` | 裁剪日志字段，只向 ManyRouter 返回测量和归属所需数据 |
| `service/manyrouter/sync.go` | 所有权校验、期望状态规范化、差异计算和事务组织 |
| `model/manyrouter_sync.go` | 跨 SQLite、MySQL、PostgreSQL 的事务写入和幂等记录 |
| `router/api-router.go` | 注册独立于普通用户和管理员身份的同步路由 |

## 3. 站点同步令牌

- 每个 New API 实例设置一个至少 32 字节的随机令牌，配置名为 `MANYROUTER_SYNC_TOKEN`。
- 轮换期间可以同时设置 `MANYROUTER_SYNC_TOKEN_PREVIOUS`，确认 ManyRouter 已使用新令牌后删除旧值。
- New API 只在内存中读取令牌，使用恒定时间比较，不写数据库、不打印日志、不返回浏览器。
- ManyRouter 继续通过现有凭证库加密保存站点令牌；新站不再保存 New API 超级管理员访问令牌。
- 令牌只允许访问 `/api/manyrouter/sync/*`，不能调用普通 `/api/channel`、`/api/option`、用户或模型转发接口。
- 远程访问必须使用 HTTPS 或受保护私网；正式 Compose 默认只在容器私网暴露同步接口。

旧站点记录继续识别原管理令牌。站点能力检查确认整批合同可用后，运营人员可以轮换为窄权限令牌；切换失败时保持原凭证和上一版线路。

## 4. New API 专用接口

### 4.1 能力查询

`GET /api/manyrouter/sync/capabilities`

返回：

- 合同版本 `m4-managed-sync-v1`。
- New API 构建版本和数据库类型。
- 是否支持整批事务、受管渠道、多分组、分组倍率、入口开放、持久幂等和最终摘要。
- 分组长度、单批渠道数、模型数和请求体大小限制。
- 当前重试次数和可重试状态码范围。

ManyRouter 根据能力字段判断，不只比较版本字符串。构建版本用于定位问题和匹配已经验证的版本组合。

### 4.2 受管状态读取

`GET /api/manyrouter/sync/state`

只返回：

- 标签符合 `manyrouter:<关系编号>` 的渠道。
- ManyRouter 当前拥有的专属分组和固定 Auto 分组。
- 这些分组的倍率和用户入口状态。
- 受管状态摘要、更新时间和资源数量。

响应不包含渠道密钥、普通用户、非受管渠道详情和非受管分组价格。ManyRouter 使用该接口完成写入前差异计算和写入后独立核对。

### 4.3 整批应用

`PUT /api/manyrouter/sync/state`

请求包含：

- 操作编号和期望线路版本。
- 写入前读取到的受管状态摘要。
- 完整受管渠道、凭证、模型映射、优先级、权重和启停状态。
- 完整受管分组倍率和入口开放状态。

处理顺序：

1. 验证令牌、请求体大小、操作编号和合同版本。
2. 规范化并验证全部字段，发现一项错误则整批拒绝。
3. 检查渠道标签、分组标识和现有资源归属。
4. 比较当前摘要；存在并发修改时返回冲突，不覆盖新状态。
5. 在一个数据库事务中创建、更新或停用受管资源，并合并全局分组设置中的受管键。
6. 提交后刷新渠道能力、渠道缓存和系统设置缓存。
7. 再读受管状态，保存不含密钥的审计与幂等结果。
8. 返回每项动作和最终摘要。

同一操作编号和相同请求返回原结果；相同编号用于不同请求返回冲突。幂等记录保存 24 小时，不保存渠道密钥正文。

### 4.4 日志读取

`GET /api/manyrouter/sync/logs`

- 只允许读取调用成功和调用失败两类日志，并限制单页最多 100 条。
- 返回时间、模型、令牌量、耗时、流式状态、渠道、分组、请求编号和已有错误归属元数据。
- 不返回用户名、令牌名称、用户编号、用户 IP 和渠道密钥。
- ManyRouter 优先使用该接口；旧站点返回未授权或不存在时，继续使用原管理员日志接口。

## 5. 受管边界

- 渠道所有权由合法的 `manyrouter:<UUID>` 标签确认，名称不能作为所有权依据。
- 专属分组和固定 Auto 分组必须由现有稳定生成函数得到，不能接受任意前缀字符串。
- 创建渠道只能使用受管标签；更新和停用只能命中同标签的现有渠道。
- 请求中消失的受管渠道改为停用，首版不自动删除，便于审计和恢复。
- 全局分组设置采用按键合并，只增删当前受管键，保留其他键和值原样不动。
- 发现标签冲突、一个标签对应多条渠道或受管分组被非受管渠道占用时，整批拒绝并要求人工处理。
- New API 人工停用的受管渠道继续作为安全锁；没有明确恢复标记时整批同步不能重新启用。

## 6. 事务、缓存与故障

- 数据库变化在 New API 主库单事务完成，兼容 SQLite、MySQL 和 PostgreSQL。
- 数据库提交前不更新进程缓存；提交失败时外部状态保持原样。
- 数据库提交成功但缓存刷新失败时返回结果未知，ManyRouter 通过状态读取确认，不盲目重发不同操作。
- 多个 New API 节点依赖现有缓存刷新机制；没有 Redis 广播能力的版本不进入正式兼容组合。
- ManyRouter 仍保存每一步状态和最后确认线路。New API 整批返回成功后仍必须重新读取核对。
- 能力不兼容、令牌无效或所有权冲突属于人工处理；超时和临时不可达进入现有重试队列。

## 7. 兼容清单

仓库维护版本化兼容清单，记录：

- ManyRouter 版本、New API 构建版本和整批合同版本。
- 已验证数据库类型和版本。
- 支持能力、已知限制、升级来源与最低回退版本。
- 合同测试和真实验收记录。

正式站点只使用清单中验证通过的组合。未知构建若能力完全匹配，可以进入“待验证”只读状态；完成合同和真实测试后才进入推荐组合。

## 8. 运营接口与页面

ManyRouter 提供：

- 手动重新检查单个站点兼容能力。
- 查看合同、构建版本、数据库类型、限制、重试配置、最近检查时间和阻塞原因。
- 查看站点当前使用整批同步或旧接口同步。
- 轮换站点同步令牌时沿用现有站点凭证更新流程。

站点不兼容时继续展示当前业务状态，但禁用会扩大或恢复流量的写操作；安全停用仍按已确认能力执行。

## 9. 当前实现

截至 2026-09-07，New API fork 已在提交 `58e7a9af` 实现窄令牌鉴权、能力查询、受管状态读取、事务整批应用、裁剪日志读取和手机产品指标横向查看。接口只返回受管渠道、分组与测量所需日志字段，不返回渠道密钥和用户身份字段；整批应用会预检真实渠道、保留非受管资源和人工停用锁，并保存 24 小时持久幂等结果。内部渠道预检产生的“模型测试”日志在源端排除，不会污染真实流量采集。

ManyRouter 已实现对应客户端和整站同步执行：支持能力、状态、重试、计费依据与日志读取；能力可用时一次提交站点完整渠道与分组状态，写入后再次读取并核对，再逐项确认渠道绑定、凭证版本、价格和线路版本。旧站点的专用接口返回未授权或不存在时继续使用原管理接口。

兼容清单、检查历史、15 分钟定时检查、手动立即检查和运营详情已经实现。正式整批同步前会核对最新检查是否批准同一构建、合同和数据库类型；没有批准记录时停止写入。

## 10. 验证方式

- New API 合同测试覆盖无令牌、错误令牌、当前和上一令牌、请求过大、未知字段和错误合同。
- 所有权测试覆盖非受管渠道保留、标签冲突、固定 Auto 分组占用和人工停用锁。
- 幂等与并发测试覆盖相同操作重放、不同请求复用编号、旧摘要冲突和双请求竞争。
- 数据库测试在真实 SQLite、MySQL 和 PostgreSQL 上覆盖新建、升级、重复启动、事务回滚和现有数据保留。
- ManyRouter 合同测试覆盖能力判断、批量成功、超时后重读、结果未知、旧接口回退和不兼容只读。
- 真实验收比较同步前后全部非受管资源，确认数量和内容不变。

当前自动化结果：New API 的 SQLite 合同测试、MySQL 8.4 与 PostgreSQL 17.6 数据库矩阵、裁剪日志合同、定向 `go vet` 和竞态检查通过；ManyRouter 的 New API 适配器、日志回退、兼容规则、整站同步批准门槛与 PostgreSQL 检查历史测试通过。
