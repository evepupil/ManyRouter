# 自动线路发布与故障恢复模块设计

> 模块定位：把 M2 的完整评分批次转换为固定 Auto 成员变化，通过现有线路版本与同步能力安全发布，并依靠 New API 原生重试完成首字前故障切换
> 对应代码：`internal/domain/automation`、`internal/application/automation`、`internal/adapters/storage/postgres/automation_read.go`、`internal/adapters/storage/postgres/automation_write.go`、`internal/adapters/storage/postgres/scoring_runs.go`、`internal/adapters/gateway/newapi/automation.go`、`internal/adapters/gateway/newapi/retry.go`、`internal/jobs/automation.go`、`db/migrations/00007_m3_automation_catalog.sql`、`internal/application/reconciliation`、`internal/domain/routing`、`api/operations.yaml`、`web/src/features/auto`
> 所属里程碑：[M3 - 跑通固定 Auto 用户产品闭环](../roadmap.md#m3)
> 当前状态：进行中
> 最近更新时间：2026-09-06
> 架构依据：[评分与状态](../架构设计.md#17-评分与状态架构)、[策略架构](../架构设计.md#18-策略架构)、[New API 配置同步](../架构设计.md#20-new-api-配置同步架构)、[一致性模型](../架构设计.md#23-一致性模型)、[故障处理](../架构设计.md#24-故障处理)

## 1. 职责与边界

本模块负责：

- 只接收同一站点、同一统计时点、同一规则版本的完整评分批次。
- 按固定 Auto 汇总模型级建议，生成供应商记录级的加入、保留、退出和排除决定。
- 保存自动调整开关、执行批次、逐项决定、使用的评分依据和关联线路版本。
- 复用 M1 的完整站点线路、同步、核对和历史恢复能力发布成员变化。
- 在数据过期、评分不完整、线路正在处理或存在人工安全锁时冻结不安全变化。
- 检查 New API 原生重试配置，并验证首字前失败能够切换到同组其他渠道。
- 保证普通成员变化不创建价格版本，不改变当前已经生效的用户售价。

本模块不负责重新计算 M2 分数、自动调整售价、创建用户自定义 Auto，也不参与每次用户请求。M4 的窄权限整批同步继续作为正式集成增强项。

## 2. 结构与数据流

### 2.1 代码结构

| 位置 | 职责 |
|---|---|
| `internal/domain/automation/` | 完整批次检查、模型建议汇总、成员变化、安全冻结和恢复规则 |
| `internal/application/automation/` | 组织站点自动调整、持久化决定、生成线路和触发同步 |
| `internal/adapters/storage/postgres/automation_read.go` | 读取可执行评分批次、自动设置、候选、决定和运行历史 |
| `internal/adapters/storage/postgres/automation_write.go` | 锁定站点配置，在同一事务保存决定、成员、安全停用、线路和同步任务 |
| `internal/adapters/storage/postgres/scoring_runs.go` | 保存完整评分批次及目标完成情况 |
| `db/migrations/00007_m3_automation_catalog.sql` | 自动设置、运行、决定、安全停用、产品令牌和产品快照表结构 |
| `internal/adapters/gateway/newapi/automation.go`、`retry.go` | 读取 New API 重试次数和可重试状态码，给出自动调整兼容结果 |
| `internal/jobs/automation.go` | 周期扫描及单站任务 |
| `internal/application/reconciliation/` | 继续执行线路差异、外部写入、最终回读和失败分类 |
| `web/src/features/auto/` | 自动调整开关、最近决定、阻塞原因、同步结果和恢复入口 |

### 2.2 数据流

```text
M2 完整评分批次
    -> 检查站点、规则版本、统计时点、数据新鲜度和目标完整性
    -> 按固定 Auto 与供应商记录汇总全部启用模型
    -> 形成成员变化与自动安全停用决定
    -> 同一事务保存决定、策略版本、线路版本和同步任务
    -> New API 顺序写入并最终回读
    -> 成功后确认线路；失败或未知时保留可追踪状态
```

## 3. 核心数据

| 数据 | 作用 |
|---|---|
| 评分批次 | 标识同一统计时点应覆盖的全部站点目标；只有站点内全部目标成功才可自动使用 |
| 自动调整设置 | 按站点和固定 Auto 保存人工维护或自动调整模式、业务版本和最近修改人 |
| 调整运行 | 保存站点、评分批次、开始与结束时间、状态、是否产生线路及失败摘要 |
| 调整决定 | 保存 Auto、供应商记录、原成员状态、目标状态、动作、原因和评分快照引用 |
| 自动安全停用 | 保存由系统创建的全局或站点范围停用及原因；只能由本模块在恢复条件满足后解除 |
| 线路引用 | 将一次调整运行关联到生成的策略版本、线路版本和同步操作 |

所有决定均为追加记录。重跑同一评分批次只能复用原结果，不能生成重复策略版本。

## 4. 自动调整规则

### 4.1 模型建议汇总

当前 Auto 成员按供应商投放关系保存，M2 建议按模型保存。M3 首期使用保守汇总：

- 非成员只有在全部启用模型都给出明确加入建议时才加入。
- 当前成员任一启用模型给出明确退出建议时，整条供应商记录退出该 Auto。
- 任一启用模型触发真实性、凭证、余额或已确认重大风险时，整条记录立即排除。
- 观察、证据不足、数据过期或不同模型结论冲突时保持当前成员状态。
- 需要逐模型独立管理时，由运营人员拆成不同供应商记录；后续再按真实需求启用一供应商多渠道能力。

### 4.2 动作与生效

| 评分建议 | 当前情况 | 自动结果 |
|---|---|---|
| 加入 | 当前不在 Auto，全部模型通过 | 加入成员 |
| 保留 | 当前已在 Auto | 不变 |
| 退出 | 当前已在 Auto，普通表现连续低于退出线 | 移出该 Auto，保留专属入口 |
| 排除 | 出现已确认硬风险 | 立即移出所有 Auto，并按风险范围创建自动安全停用 |
| 观察 | 数据不足、等待连续确认或结论冲突 | 不变 |

成员变化后若某个模型已无任何合格成员，关闭该 Auto 用户入口并记录告警。恢复至少需要连续两个完整合格评分批次；人工停用和 New API 人工锁不会被自动恢复。

### 4.3 冻结条件

出现以下任一情况时，不执行自动加入、恢复或扩大可用范围：

- 站点采集状态有缺口或事实更新时间超过允许范围。
- 评分批次缺少目标、混用统计时点或规则版本。
- 站点版本、策略版本或候选供应商范围在计算后发生变化。
- 当前线路仍在同步、结果未知或等待人工处理。
- New API 版本或重试配置未通过 M3 兼容检查。

硬风险退出允许在数据扩张冻结时继续执行，但必须基于仍在有效期内的已确认硬证据。

## 5. 事务、并发与幂等

1. 每次评分先保存批次及预期目标数，全部目标完成后才标为可用。
2. 自动任务按站点领取，并取得与人工策略修改、价格发布和线路生成相同的站点锁。
3. 锁内重新读取评分批次、自动设置、人工状态、当前策略版本和线路状态。
4. 没有变化时保存一次无变更运行，不生成策略或线路版本。
5. 有变化时在同一数据库事务内保存决定、更新成员、生成新策略版本、线路版本及同步任务。
6. 同一站点、Auto 和评分批次只有一份决定；任务重复领取时直接返回已有结果。
7. 人工修改造成版本冲突时放弃本轮，等待下一完整评分批次重新计算。

## 6. 线路发布、失败与恢复

- 线路快照继续包含全站供应商、Auto、当前价格版本、入口状态和策略版本引用。
- 普通调整等待当前线路进入终态；硬风险可以生成更高版本并使旧待执行计划失效。
- New API 外部写入继续遵循“读实际状态、计算差异、写入、最终回读”的过程。
- 外部结果未知时先重读，不盲目重复创建渠道或分组。
- 部分写入失败继续保存逐步骤结果；整站未最终一致前不标记调整已生效。
- 恢复使用最近已确认线路的业务内容生成一个新版本，不移动历史指针，也不恢复旧凭证。
- 自动任务只能解除自身创建的安全停用；人工停用必须由运营人员显式恢复。

## 7. New API 原生故障切换

ManyRouter 不实现转发或重试。固定 Auto 仍由 New API 按分组选择渠道、转发、计费和写日志。

自动调整开启前需要确认：

- 目标版本支持同一分组内多渠道选择。
- 重试次数至少为 1，连接错误和约定状态码允许重试。
- 重试会避开本次请求已经失败的渠道。
- 目标模型至少存在两条已确认可用的 Auto 成员线路，才能声明具备故障切换能力。
- 流式内容已经输出后不进行自动重放。

兼容检查只读取 New API 重试配置，不自动覆盖站点管理员维护的全局设置。配置不满足时，自动成员调整保持关闭并显示具体缺口。

## 8. 运营接口与页面

M3 增加以下能力：

- 按站点读取五种固定 Auto 的维护模式、最近完整评分批次和最近调整结果。
- 保存单个 Auto 的人工维护或自动调整模式，要求当前业务版本一致并填写原因。
- 手动触发一次站点自动评估；人工维护模式只生成预览，自动调整模式允许生成线路。
- 查询调整运行和逐项决定，展示业务名称、原成员、目标成员、原因、线路状态和时间。
- 从失败调整进入现有同步详情或历史线路恢复入口。

页面继续使用现有站点范围、表格、状态和弹窗组件。自动调整开关属于高影响操作，开启前显示兼容检查与冻结条件，提交期间锁定弹窗。

## 9. 验证方式

- 纯规则测试覆盖五类建议汇总、多模型冲突、数据冻结、硬风险、最后成员退出和连续恢复。
- 应用测试覆盖完整批次、无变化、版本冲突、重复任务、人工优先和自动停用所有权。
- PostgreSQL 集成测试覆盖站点锁、决定与策略/线路同事务、双站隔离和任务重领。
- New API 合同测试覆盖重试配置读取、首字前连接失败与 5xx 切换、已输出流不重放。
- 真实验收覆盖两个独立 New API 进程、两条 Auto 成员线路、一次受控失败、价格不变、历史可查和临时资源清理。

截至 2026-09-06 已完成的验证：

- 领域与应用测试覆盖加入、观察、退出、硬风险排除、系统安全停用、恢复、人工预览、完整批次和过期冻结。
- PostgreSQL 17.6 完整集成套件通过，确认自动决定、成员、安全停用、线路及同步任务同事务保存，并验证产品数据按站点隔离。
- 最新本地 New API 二进制合同测试通过：HTTP 500 在首字节前切换到低优先级健康线路；首选线路输出 SSE 后异常断开时，备用线路调用次数为零。
- Impeccable 对 Auto 与站点令牌相关界面文件的静态检测没有发现问题。

仍需真实验收两个独立 New API 实例上的自动发布、价格保持和历史查询；自动执行在此之前继续保持默认关闭。

## 10. 当前实现

截至 2026-09-06，完整评分批次、五种固定 Auto 的人工/自动维护模式、自动加入与退出、硬风险系统停用、合格恢复、版本化线路发布、同步结果映射、调整历史和 New API 重试兼容检查均已实现。周期任务只领取已经开启自动维护的站点，自动维护默认关闭；人工停用与系统停用分开保存，自动任务只能解除自身创建的安全停用。运营页面可以切换维护方式、手动执行一次评估，并查看逐项决定及线路状态。

当前代码和自动化验证已经完成，M3 仍为进行中，等待两个独立 New API 实例上的真实发布验收，并受 M2 剩余真实性与采集验收约束。
