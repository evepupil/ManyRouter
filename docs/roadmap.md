## 项目目标

ManyRouter 统一管理多个 New API 站点的供应商、分组、策略和价格，根据可信的真实流量与主动测评维护固定及自定义 Auto，并向用户提供可解释、价格稳定、能够自动避开异常供应商的 AI API 服务。

## 交付边界

- M0 完成单站真实接入，禁止用模拟 New API 代替退出验收。
- M1 完成可人工运营的多站产品，固定 Auto 由人工维护；按[验收口径](./需求设计.md#m1-acceptance-scope)分别报告供应商记录数与真实上游数，多厂商差异留待后续运营验证。
- M2 只生成评分和调整建议，真实分组仍由运营人员决定。
- M3 同时交付固定 Auto 自动调整和 New API 用户页面，形成可用的自动运营 MVP。
- M4 完成正式接入、兼容验证和重复建站，形成当前需求中的首个正式商业版本。
- M5 增加用户级策略与报价，不阻塞固定 Auto 上线。

## 后续方向

多地区测评、供应商自助入驻、其他网关、同一供应商多套凭证、统一跨站账户和动态插件系统等待真实运营需求后再进入新里程碑。

## 模块设计规则

M0 已有三份模块文档；M1 已确认扩充这三个模块并新增人工策略、稳定价格、运营账号与权限、运营控制台四个模块。M2 已确认真实流量采集与测量事实、主动测评与模型真实性、窗口统计与影子评分三个模块。M3 已确认自动线路发布与故障恢复、用户产品数据与 New API 页面两个模块。M4 已确认 New API 正式集成与兼容、组合发布与新站初始化、运行监控与升级回退三个模块。后续里程碑仍需在开始前结合对应架构分层讨论模块边界；用户确认后再创建对应文档并补齐双向链接。

## 进度依据

M1 已按 3 个独立供应商记录、1 个真实上游、2 个独立 New API 实例通过[最终真实验收](./验收/M1-真实验收-2026-09-05.json)。M2 已通过[基础真实验收](./验收/M2-真实验收-2026-09-06.json)：两站日志逐条对账，3 轮健康和 3 轮质量测评完成，两轮各 96 个真实性样本完成可信参考提升与同上游一致对比，两站各保存 12 份可解释评分快照，且评分未修改真实线路。真实中断续传、ClickHouse 稳定日志键、生产可信参考、多时段盲测、不同模型反例和站点链路专用探测仍待完成；M2 保持进行中，退出标准不变。

M3 主体代码和自动化验证已完成，并通过[本地单站真实验收](./验收/M3-本地单站真实验收-2026-09-07.json)：PostgreSQL New API 显示 3 条专属产品和三成员均衡 Auto，真实调用记录 `4 -> 1` 首字前切换，M2 日志进入产品 SLA，自动维护以 3 条保留决定无变化结束。第二个独立 New API、账号隔离、真实证据驱动的自动成员变化与连续恢复仍待验收，M3 保持进行中。

M4 已确认三个模块并开始实现：正式站点使用窄权限整批同步和能力合同；发布组合采用单机 Linux/WSL Docker Compose 与 PostgreSQL；运行维护提供统一状态、低基数指标、人工升级和应用回退。M4 完成仍需同一版本组合从零建立第二站并通过真实升级回退验收。
