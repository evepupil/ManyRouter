# 运行监控与升级回退模块设计

> 模块定位：让运营人员看到当前组合是否健康，并用可检查的备份、升级、冒烟和回退流程维护正式站点
> 对应代码：`internal/application/runtimehealth`、`internal/adapters/storage/postgres/runtime_health.go`、`internal/transport/http/runtime_health.go`、`internal/platform/observability`、`api/operations.yaml`、`web/src/features/runtime-health`、`scripts/release/upgrade.ps1`、`scripts/release/rollback.ps1`
> 所属里程碑：[M4 - 完成正式集成与可复制发布](../roadmap.md#m4)
> 当前状态：进行中
> 最近更新时间：2026-09-07
> 架构依据：[身份、审计与通知](../架构设计.md#813-身份审计与通知)、[一致性模型](../架构设计.md#23-一致性模型)、[故障处理](../架构设计.md#24-故障处理)、[发布与回退](../技术设计.md#20-发布与回退)

## 1. 职责与边界

本模块负责：

- 汇总站点兼容、线路同步、日志采集、评分、自动调整、产品快照和后台任务状态。
- 提供机器可读健康接口和 Prometheus 指标。
- 在控制台提供安静、可扫描的运行状态页面和处理入口。
- 在升级前保存数据库备份、当前发布组合和最近确认线路证据。
- 在升级后运行兼容检查和冒烟测试，失败时切回上一组镜像。
- 保留升级、回退、检查和人工决定的审计记录。

本模块不替代外部主机监控、日志平台或数据库备份服务。首版不自动执行生产升级，也不自动恢复数据库到旧结构。

## 2. 运行状态模型

运行状态分为四级：

| 状态 | 含义 | 默认动作 |
|---|---|---|
| 正常 | 当前组合受支持，关键任务和站点数据在允许时间内 | 继续运行 |
| 注意 | 数据或任务接近过期，但用户请求仍可用 | 观察并安排处理 |
| 阻塞 | 新配置不能安全发布，上一版仍在服务 | 停止扩大和恢复流量 |
| 故障 | 核心数据库、站点管理接口或任务持续失败 | 告警并按运行手册处理 |

状态由事实字段计算，数据库只保存原始检查结果和历史事件，不保存无法解释的单一颜色结论。

## 3. 汇总内容

### 3.1 系统级

- ManyRouter 构建版本、数据库迁移版本和启动时间。
- 当前兼容清单版本与推荐 New API 组合。
- PostgreSQL 连通性、连接池占用和数据库时间偏差。
- River 等待、执行、可重试、永久失败和最老等待任务。
- 最近一次周期采集、评分、自动调整任务时间。

### 3.2 站点级

- New API 构建版本、同步合同、数据库类型和兼容结论。
- 最近确认线路、待同步线路、最近失败步骤和重试时间。
- 日志游标、源端最新时间、连续失败和数据缺口。
- 最新完整评分时间、证据状态和自动调整模式。
- 最新产品快照、事实截止时间和用户数据新鲜度。

### 3.3 供应商级

首版复用现有评分和测评页面，不在运行状态页重复展示全部供应商指标。运行状态页只列出影响站点发布或需要人工处理的供应商问题。

## 4. 接口

- `GET /api/v1/ops/runtime-health`：系统汇总和全部站点摘要。
- `GET /api/v1/ops/runtime-health/{site_id}`：单站详细事实、阻塞原因和建议动作。
- `POST /api/v1/ops/runtime-health/{site_id}/check`：立即执行兼容、受管状态和数据新鲜度检查。
- `GET /metrics`：Prometheus 文本格式指标，不包含站点令牌、供应商密钥、用户名和高基数请求编号。
- `GET /api/v1/healthz`：继续作为进程存活检查；数据库依赖状态由运行状态接口提供。

立即检查使用现有请求编号和身份审计。读取接口不触发同步或自动修改线路。

## 5. 指标

首版提供低基数指标：

- `manyrouter_build_info`。
- `manyrouter_database_up`。
- `manyrouter_jobs{state}`。
- `manyrouter_site_compatible{site}`。
- `manyrouter_site_sync_age_seconds{site}`。
- `manyrouter_site_collection_age_seconds{site}`。
- `manyrouter_site_product_age_seconds{site}`。
- `manyrouter_site_pending_operations{site}`。

站点标签使用稳定短码，不使用 UUID、供应商名称或请求编号。请求级延迟和业务用量继续来自 New API 与 M2，不在控制面重复采集。

## 6. 控制台页面

侧栏新增“运行状态”，使用现有页面、表格、状态、按钮和弹窗组件：

- 顶部显示当前发布组合和总状态。
- 主表每行一个站点，展示兼容、线路、采集、产品数据和任务状态。
- 只在存在问题时显示原因和建议处理动作。
- 提供刷新、立即检查、进入同步详情和查看兼容信息。
- 加载、空数据、读取失败、长错误文本和窄屏均沿用现有组件行为。

页面不展示版本规划、内部堆栈、令牌摘要或无行动价值的“在线”文案。

## 7. 升级流程

生产升级只由运营人员显式执行：

1. 运行只读预检，确认当前服务健康和目标组合受支持。
2. 使用 `pg_dump` 分别备份 ManyRouter、New API 业务库和日志库。
3. 保存当前环境文件摘要、镜像摘要、迁移版本和最近确认线路编号。
4. 拉取目标不可变镜像，先运行数据库迁移检查。
5. 依次切换 New API 和 ManyRouter，等待健康检查。
6. 运行能力、受管状态、产品页和真实调用冒烟。
7. 成功后写入发布记录并保留上一组镜像。

脚本不修改供应商配置、价格或 Auto 成员。升级过程中 New API 用户请求尽量由当前容器继续服务；单机 Compose 切换会有短暂连接中断，必须在运行说明中明确。

## 8. 回退流程

- 应用或合同检查失败时，切回升级前保存的镜像摘要和环境文件。
- 回退后重新读取 New API 受管状态和 ManyRouter 最近确认线路，不直接覆盖业务状态。
- 数据库迁移必须保证至少向后一版应用兼容；不满足时该版本不能进入推荐组合。
- 需要恢复数据库备份时停止自动任务，由运营人员确认备份时间和会丢失的升级后数据后执行。
- 回退完成后运行与升级相同的健康和产品冒烟，并保存失败原因。

## 9. 当前实现

截至 2026-09-07，统一运行状态已经实现：应用层从兼容检查、线路同步、日志采集、评分、自动维护、产品快照和 River 任务计算四级状态；PostgreSQL 保存原始兼容检查历史并汇总现有事实。接口支持系统汇总、单站详情和带请求编号的立即检查。

控制台已增加“运行状态”页面，按站点展示兼容、线路、采集、评分、自动维护、产品数据和待处理原因，并提供立即检查、详情和同步记录入口。`/metrics` 已提供设计中的低基数指标，站点标签只使用稳定站点短码。

升级脚本会先备份三个数据库、保存升级前环境和镜像，再同时更新镜像、ManyRouter 构建版本、ManyRouter 提交和 New API 构建版本，并运行相同冒烟；失败时自动恢复上一组镜像和环境。脚本不会自动恢复数据库。真实升级与应用回退仍待当前 WSL 组合验收。

## 10. 验证方式

- 状态计算单测覆盖正常、注意、阻塞、故障、无数据和时间过期。
- PostgreSQL 集成测试覆盖任务统计、双站隔离和检查历史。
- HTTP 与页面测试覆盖权限、立即检查幂等、错误清洗和各状态展示。
- 指标测试确认名称稳定、标签有界且不含秘密或个人数据。
- 使用当前 WSL 组合完成一次升级和应用回退，比较前后渠道、价格、令牌、产品和历史记录。
- 人工确认上一版本在新迁移结构上仍能启动，或在兼容清单中明确禁止应用回退。
