# 单站线路方案模块设计

> 模块定位：把站点供应商关系转换成与网关无关、可以版本化和核对的单站期望配置
> 对应代码：`internal/domain/routing`、`internal/application/onboarding`、`internal/application/operations`、`internal/adapters/storage/postgres`
> 所属里程碑：[M0 - 跑通单站供应商接入闭环](../roadmap.md#m0)、[M1 - 跑通多站人工运营闭环](../roadmap.md#m1)
> 当前状态：已完成
> 最近更新时间：2026-09-05

## 1. 职责与边界

本模块负责：

- 根据站点、供应商、模型、销售倍率和投放关系生成一份完整期望状态。
- 为每个站点维护单调递增的线路版本。
- 生成稳定、可比较的渠道和专属分组描述。
- 发现业务配置没有实质变化时复用当前版本。
- 为同步模块提供网关无关的输入，并保存不可修改的历史快照。

本模块不负责：

- 调用 New API 或理解 New API 请求字段。
- 读取真实流量、计算评分或决定 Auto 成员。
- 自动计算销售价格。
- 判断外部写入是否成功。

## 2. 输入与输出

### 2.1 输入

- 已启用站点。
- 已启用供应商及其当前凭证版本。
- 已启用供应商模型和模型映射。
- 一份站点供应商关系。
- 人工确认的销售倍率、入口开放状态和期望启停状态。

### 2.2 输出

```text
单站期望状态版本
├─ 站点身份与版本号
├─ 生成原因和生成时间
├─ 专属分组
│  ├─ 稳定内部名
│  ├─ 展示名
│  ├─ 销售倍率
│  └─ 用户入口开放状态
└─ 受管渠道
   ├─ 稳定受管标记
   ├─ 供应商协议和地址
   ├─ 凭证版本引用
   ├─ 模型及上游模型映射
   ├─ 所属专属分组
   ├─ 优先级与权重
   └─ 期望状态
```

期望状态只引用凭证版本，不包含明文密钥。同步执行到具体站点时才通过凭证能力取得明文。

## 3. M0 期望状态规则

### 3.1 专属分组

- 每份站点供应商关系恰好生成一个专属分组。
- 内部名使用关系身份生成，展示名变化不创建新分组。
- M0 销售倍率为大于零、最多六位小数的十进制值。
- M0 记录用户入口开放意图；关闭入口后 New API 会拒绝已有该组 API Key 的请求。

### 3.2 渠道

- M0 每份关系生成一个 OpenAI 兼容渠道。
- 渠道携带稳定受管标签、供应商地址、当前凭证版本、模型列表和专属分组。
- 初次创建使用观察状态。连通测试成功后，同一次同步操作才可以将它启用。
- 优先级默认为 `0`，权重默认为 `100`。M0 不根据评分调整这两个值。
- 模型名和上游模型名不同才生成模型映射；相同名称不产生多余映射。

### 3.3 价格

- M0 把人工确认的销售倍率写入专属分组。
- 倍率进入期望快照后保持不变，普通重复同步不会重新计算。
- 采购价格只用于运营记录，不在 M0 自动换算倍率。
- 金额和倍率以十进制字符串进入规范化快照，避免浮点误差造成无意义新版本。

## 4. 版本与规范化

- 同一站点的线路版本从 `1` 开始严格递增。
- 生成前按照固定字段顺序、模型名排序和标准十进制格式形成规范化内容。
- 对规范化内容计算 SHA-256 摘要。
- 摘要等于站点当前期望版本时不创建新版本，也不重复安排同步。
- 新版本保存完整快照、上一版本、生成原因和操作者。
- 已保存快照不允许修改；纠正配置必须生成下一版本。
- M0 每个版本只包含一个投放关系，数据格式允许 M1 将同站多个关系汇总进一个版本。

## 5. 状态变化

```text
业务资料有效
      │
      ▼
生成 pending 线路版本
      │
      ├─ 同步成功并核对一致 ─► confirmed
      ├─ 存在明确错误       ─► failed
      └─ 写入结果未知       ─► uncertain
```

- `pending` 表示已经保存、等待同步。
- `applying` 表示同步模块正在处理。
- `confirmed` 表示重新读取后的受管资源与快照一致。
- `failed` 表示存在可理解的明确失败，可重试错误由任务系统重新安排。
- `uncertain` 表示请求可能已经在 New API 生效，后续只能先读取核对。
- 同一站点同时只允许一个版本处于 `applying`。

## 6. 差异输入约束

线路方案不会自己计算 New API 差异。它向同步模块提供：

- 期望分组内部名和倍率。
- 期望渠道受管标签、配置和状态。
- 已保存的 New API 渠道编号绑定，可能为空。
- 最近确认版本和资源摘要。

同步模块返回实际摘要和逐项结果后，本模块只在全部关键字段一致时把版本标记为 `confirmed`。

## 7. 关键决策

1. 线路方案保存业务结果，New API 字段和状态数字全部留在网关适配层。
2. 线路版本、价格版本和未来评分版本分别保存，M0 的人工倍率不会被重复同步改写。
3. 使用完整快照与内容摘要，支持审计、重复执行和后续回放。
4. 初次渠道先观察和测试，再启用，避免无效密钥直接进入用户流量。
5. M0 不生成 Auto 分组，减少真实闭环中的无关变量。

## 8. 当前实现（M0）

- 已实现站点、供应商和投放关系到单站期望状态的转换。
- 已实现稳定专属分组名、稳定渠道标签、模型排序、十进制规范化和 SHA-256 内容摘要。
- 已实现站点级事务锁、单调递增线路版本、完整 JSON 快照和当前版本绑定。
- 相同业务输入会产生相同快照摘要。摘要已经保存，投放关系更新接口将在后续实现时据此跳过无实质变化的版本。
- 自动化集成测试和真实站点都已产生并确认首份线路版本；保存的渠道、分组和倍率与 New API 重读结果一致。

## 9. 验证方式

- 单元测试覆盖稳定命名、模型排序、十进制规范化和摘要稳定性。
- 单元测试覆盖相同输入不产生新版本、业务变化生成下一版本。
- 单元测试覆盖无模型、无凭证、非法倍率和禁用站点拒绝生成。
- PostgreSQL 集成测试覆盖站点版本单调递增和同站并发生成。
- 真实验收确认保存快照与 New API 重读结果一致。

已通过：

- 模型输入顺序变化不影响快照和摘要。
- 销售倍率按标准十进制保存，不产生浮点漂移。
- 站点供应商关系、实际渠道绑定和首份线路版本在同一数据库事务中落地。
- PostgreSQL 17 中的线路版本、当前关系和价格精度集成验证。
- 真实站点首份线路版本进入 `confirmed`，投放关系进入 `active`。

## 10. M1 扩充设计

### 10.1 完整站点快照

每次保存有效运营变更，汇总该站全部投放关系、专属分组、人工 Auto 和价格引用，形成一份完整站点计划。输入由[站点与供应商接入](./站点与供应商接入.md)、[人工策略管理](./人工策略管理.md)和[稳定价格管理](./稳定价格管理.md)提供，外部执行仍交给[New API 同步与核对](./New%20API同步与核对.md)。

```text
站点期望配置（格式版本 2）
├─ 站点身份、业务版本、内容摘要
├─ 各投放关系的资源集合
│  ├─ 供应商、关系与实际渠道的稳定身份
│  ├─ 专属分组、入口开放状态、价格与价格版本
│  └─ 渠道地址、凭证版本、模型、所属全部分组、期望启停
├─ 本站固定 Auto 分组、展示与独立价格版本
├─ 全部人工策略的源配置版本引用（包括停用和未定价策略）
└─ 本次明确要求解除人工停用的关系清单
```

M1 延续每份投放关系一个实际渠道。渠道所属分组扩为“专属分组 + 人工选入的 Auto 分组”，内部列表固定排序且去重；默认优先级 `0`、权重 `100`，M1 不引入按 Auto 分别分配渠道权重。停用关系保留在快照中并明确标记停用，不能用资源缺席来表达下线。

Auto 的关闭、空成员和成员下线规则由策略模块决定；快照保存最终有效成员集合，保留已存在组的稳定身份和价格。业务源配置中的成员选择与最终可参与调用的成员分开表示，避免供应商停用后丢失人工选择。任何可用分组必须有合法价格，成员更换不计算新售价。

线路快照保留现有 37 字符专属组键。五种固定 Auto 分组在单个 New API 实例内使用稳定短码：最低价 `mrap`、低延迟 `mral`、高 SLA `mras`、高质量 `mraq`、均衡 `mrab`，业务身份仍由 `site_id + 策略类型` 决定。单条渠道加入专属组及全部五种 Auto 时，逗号拼接后的长度为 62，满足 New API 渠道 `group` 字段最多 64 个字符的限制。短码允许跨独立实例复用，因此 M1 每个站点必须对应独立 New API 实例。

### 10.2 M0 兼容与存储

- 保留格式版本 `1` 的原始历史快照、内容摘要、版本号和确认时间；读取时可转换为单资源视图，禁止重写历史证据。
- 旧线路快照中的 `mr_a_...` Auto 组键继续可读并按原内容校验；升级前仍是当前配置的旧策略也继续使用原组键和原价格生成后续线路。短码只用于首次创建的新策略，不批量改写历史快照或现有策略。
- 新格式使用版本 `2`，包含资源集合和 Auto 集合；集合子项复用版本 `1` 的单关系结构，禁止子项继续嵌套集合。
- 沿用线路版本与同步操作表。现有非空关系引用暂保留为该站计划的代表关系；完整执行范围以快照集合为准，不能再把代表关系当作唯一受影响关系。
- 同一站点所有投放关系的当前计划引用共同指向新站点计划；历史 M0 计划仍按原关系可查。
- 第一次生成版本 `2` 时从当前全部业务关系重建；已创建的渠道与分组沿用稳定身份和外部绑定，不重新接入。
- 保留格式兼容分支直到旧任务和历史查询均已验证；未知格式版本明确拒绝执行。

### 10.3 生成事务与并发

1. 业务保存前取得该站同步锁的事务版本，检查操作者提交的预期业务版本。
2. 读取同一事务中的供应商、全部投放、策略和价格，校验身份归属、模型、有效凭证与分组引用。
3. 规范化资源、模型、分组、Auto 成员、十进制数及显式恢复指令，计算摘要；内容不变则复用当前计划。
4. 内容变化时分配下一站点版本，保存不可变快照与差异，更新全部关系的当前计划引用，并保存同步操作与持久任务。
5. 一次提交业务变更、计划和任务；事务失败则全部回滚，事务中不调用 New API。

批量投放一次保存多个站点的意图，但每站产生独立计划和外部任务。首次录入时某站无法读取计费基准，可以保存等待核对的计划，以全零摘要阻止价格写入及启用；该站恢复后，人工同步读取基准、补齐首次待确认价格并生成新计划，其他站点继续独立处理。

计划发布和同步写入使用同一个站点互斥键，保证正在执行的旧计划结束前不会发布同站新版本。同步期间业务保存可以等待至请求超时，超时返回站点忙；不允许绕过锁落地新计划。多站变更按固定站点顺序加锁，外部同步继续逐站独立执行。

格式版本、资源内容和显式恢复指令进入摘要；操作者、原因、创建时间等审计信息独立存储，不制造无意义版本。仅采购价或运营备注变化不应改变线路摘要；价格版本只在实际售价变更或明确价格决策变更时变化。

### 10.4 差异与历史恢复

按稳定身份比较前后快照，分别列出新增投放、渠道修改、启停、分组成员、入口开放状态、售价与凭证版本变化。差异不显示明文密钥或内部凭证编号；新增/移除成员列出供应商名称和归属站点。控制台展示“已保存目标”和“最近已确认配置”，不把保存成功标记为已生效。

历史线路恢复覆盖投放的展示、启停和人工策略源配置；共享供应商资料与当前有效凭证继续沿用，售价需要通过独立价格草案确认发布。恢复属于一次新的业务修改：

1. 读取选中的历史配置，与当前状态形成预览差异，保留历史来源和恢复原因。
2. 重新校验当前站点、供应商、模型、人工安全锁与价格规则；历史已删除对象和不可用模型必须明确报错。
3. 默认使用当前有效凭证；恢复历史配置不隐式恢复历史密钥，也不自动解除人工停用。
4. 在同一事务中将可恢复内容写回业务表，根据保存的策略版本引用恢复人工成员、启用与入口开放状态，生成新的策略版本和下一线路版本。恢复后继续编辑基于这些已恢复的业务值；当前已发布售价保持原值。
5. 历史 M0 单关系快照只恢复该关系，其余现存关系取当前配置，再生成完整站点计划；不能把历史缺少的其他关系视为应删除。
6. 没有策略版本引用的旧快照保留当前人工策略配置，不根据当时有效渠道成员反推并清空运营人员保存的停用策略。

### 10.5 执行状态与确认

M1 新增“已被新版本替代”状态。旧任务领取后必须在取得站点锁后重读当前计划；过期版本停止外部写入，仅保留历史结果和必要的只读核对。显式重试默认作用于最新计划，历史恢复必须经过上一节流程。

同步结果按渠道、专属组和 Auto 组记录，完整站点计划只有全部目标资源均核对一致才确认。单个渠道成功可以更新该资源的确认记录，其他资源失败时整站计划仍显示失败或结果未知；控制台通过资源结果展示部分生效。New API 现有接口多次写入，M1 不提供整站或跨站原子切换。

确认条件包含目标启停、完整分组成员、入口开放状态、价格、可读渠道配置和凭证应用证明。停用目标以读取确认停用为准，无需连通测试；启用或换密钥按同步模块规则验证。人工锁会阻止要求启用的目标确认，不把它当成已生效。

### 10.6 验证方式

- M1 按[统一验收口径](../需求设计.md#m1-acceptance-scope)使用 3～5 个独立供应商记录，允许这些记录共享同一真实上游地址、密钥和模型；仍须按独立身份生成不同投放关系、渠道及专属分组，不能因上游配置相同而合并资源。
- 两个站点必须是独立 New API 实例，配置与业务数据库彼此隔离；同一实例的重复站点记录或地址别名不能用于证明双站线路隔离。
- 版本 `1` 固定样本读取及原摘要保持；版本 `2` 编解码和未知版本拒绝。
- 多关系、模型和 Auto 输入顺序变化不影响摘要，跨站成员和重复稳定身份被拒绝。
- 容量测试覆盖 1 个专属组加 5 个固定 Auto 的最坏组合，确认完整分组字符串不超过 64 个字符，并锁定五种类型与短码的一一对应关系。
- 历史兼容测试覆盖已有 `mr_a_...` 策略更新后继续引用原价格，并在新线路中保留原组键。
- 停用供应商仍生成明确下线目标；仅凭证版本变化、成员变化和价格变化均能准确出现在差异中。
- 并发保存拒绝旧业务版本，同站线路版本严格递增，计划与任务一同回滚。
- 历史恢复生成新版本、更新业务源配置、保留当前其他供应商，拒绝自动回退旧密钥和解除人工锁。
- 部分资源失败不确认整站；旧计划重试不会覆盖新计划，双站版本与确认结果互不串线。

验收报告同时记录供应商记录数和真实上游数。共享一个真实上游可以验证完整快照、多关系、策略引用和双站版本控制，但不能证明不同厂商的独立故障、成本或能力差异，这些结论留待后续真实运营验证。首轮在 `manual_strategies` 阶段触发的 `SQLSTATE 22001` 已由短码方案解决；第二轮最终重读遇到 HTTP 429 的问题已修正为可重试。最终复验完成价格与成员隔离及后续全部场景。

## 11. M1 当前实现与验收结果

- 已实现格式版本 `2` 的资源集合、Auto 集合、明确恢复关系、价格版本引用和计费基准摘要，执行时按完整站点处理。
