# 组合发布与新站初始化模块设计

> 模块定位：把已验证的 ManyRouter、New API 和 PostgreSQL 组合做成可重复部署、可检查的新站安装包
> 对应代码：`deploy/compose.yaml`、`deploy/.env.example`、`deploy/postgres/`、`scripts/release/`、`.github/workflows/`、`cmd/manyrouter`
> 所属里程碑：[M4 - 完成正式集成与可复制发布](../roadmap.md#m4)
> 当前状态：进行中
> 最近更新时间：2026-09-07
> 技术依据：[运行与部署](../技术设计.md#19-运行与部署)、[发布与回退](../技术设计.md#20-发布与回退)、[新站注册流程](../架构设计.md#223-新站注册流程)

## 1. 职责与边界

本模块负责：

- 发布固定版本的 ManyRouter、New API 和 PostgreSQL Docker Compose 组合。
- 用本地环境文件保存站点密钥和数据库口令，仓库只提供无秘密模板。
- 初始化 ManyRouter 数据库、New API 业务库和独立日志库。
- 检查端口、目录、镜像、数据库、合同和必要配置。
- 从空环境启动服务并完成站点连接、首条线路、产品页和真实调用冒烟。
- 保存发布清单、升级说明、回退说明和最近验证证据。

首版面向单台 Linux 或 WSL 2 主机上的 Docker Compose。Kubernetes、跨地区高可用、Cloudflare 自动配置和托管数据库开通流程不在 M4 首版范围。

## 2. 发布组合

正式组合包含：

| 服务 | 数据 |
|---|---|
| ManyRouter | 独立 PostgreSQL 数据库和 named volume |
| New API | 独立 PostgreSQL 服务，业务库与日志库使用不同数据库和账号 |
| 反向代理 | 由部署环境现有入口负责，Compose 默认只绑定本机端口 |

ManyRouter 与 New API 使用不可变镜像标签和摘要。PostgreSQL 固定到已经通过测试的 17.6 小版本。Compose 不挂载数据库目录到 Windows NTFS。

## 3. 文件结构

```text
deploy/
  compose.yaml
  .env.example
  postgres/
    init-new-api.sql
  compatibility.yaml
scripts/release/
  preflight.ps1
  bootstrap.ps1
  smoke.ps1
  upgrade.ps1
  rollback.ps1
```

PowerShell 脚本统一通过 `wsl.exe -d Ubuntu-24.04 --cd /mnt/c/code/ManyRouter` 调用 Docker Compose。Linux 生产机可以直接执行脚本中列出的 Compose 命令；首版不维护第二套业务逻辑。

## 4. 配置与秘密

- `.env.example` 只包含变量名、用途和安全默认值，不包含真实密钥。
- `bootstrap.ps1` 在本机生成数据库口令、ManyRouter 主密钥、运营令牌、New API 会话密钥、站点同步令牌和站点产品令牌。
- 生成结果写入被 Git 忽略的 `deploy/.env`，文件权限尽可能限制为当前用户。
- 任何检查输出只显示是否存在、长度、摘要前缀和对应服务，不显示明文。
- New API 和 ManyRouter 通过容器私有网络互访；同步令牌不经过浏览器。
- 生产域名、TLS 和 Cloudflare Tunnel 由现有基础设施配置，Compose 不修改账户级网络设置。

## 5. 初始化流程

```text
运行 preflight
    -> 生成或读取 deploy/.env
    -> 拉取固定镜像
    -> 启动 PostgreSQL
    -> 初始化三个逻辑数据库和最小账号
    -> 启动 New API 与 ManyRouter
    -> 等待健康检查
    -> 创建 New API 所有者
    -> 在 ManyRouter 创建运营所有者
    -> 交换窄权限同步令牌和产品读取令牌
    -> 创建站点记录
    -> 运行兼容检查
    -> 可选导入供应商并生成首条线路
    -> 运行 smoke
```

脚本每一步都可重复执行。已经存在的数据库、所有者、站点和令牌不能重复创建；发现内容冲突时停止并给出人工处理信息。

## 6. 预检

预检至少检查：

- Windows 当前仓库位置、WSL 发行版、Docker 与 Compose 可用。
- Git 工作区、架构和目标端口冲突。
- `.env` 必填项、密钥长度和重复默认值。
- 镜像标签是否出现在兼容清单，拉取后摘要是否匹配。
- named volume 与目标项目名称，防止操作其他 Compose 项目。
- 现有数据库版本、可用空间和最近备份。

预检只读，不启动、停止或删除服务。

## 7. 冒烟测试

冒烟测试按影响从小到大执行：

1. PostgreSQL 连接和目标数据库存在。
2. ManyRouter 与 New API 健康接口返回成功。
3. New API 能力合同与兼容清单匹配。
4. ManyRouter 能读取站点受管状态和产品合同。
5. 重复同步不产生新渠道或修改非受管资源。
6. 使用临时 API Key 发起一次最小模型调用。
7. New API 日志出现请求，ManyRouter 采集游标推进。
8. 删除精确标识的临时 API Key，保留审计和调用日志。

真实模型调用必须由操作者显式提供供应商配置；没有真实上游时前五项仍可作为安装检查，不能标记完整验收通过。

## 8. 可复制要求

- 第一站和第二站使用同一发布清单与 Compose 文件。
- 每站生成独立数据库口令、同步令牌、产品令牌和 New API 会话密钥。
- 供应商资料可以从 ManyRouter 一次录入后投放到两个站点，New API 数据库不复制。
- 两次部署结果必须能用相同检查脚本核对。
- 清理测试站时只操作明确的 Compose 项目和 named volume；没有显式参数时禁止删除数据卷。

## 9. 当前实现

截至 2026-09-07，仓库只有 PostgreSQL 集成测试 Compose；ManyRouter 正式镜像、完整双服务 Compose、初始化脚本、固定兼容清单和可重复冒烟脚本尚未实现。当前 WSL 实例由人工命令部署，已经证明 New API 与 ManyRouter 可以在独立 PostgreSQL 上运行。

## 10. 验证方式

- 在空 named volume 上连续初始化两次，第二次不产生重复对象。
- 从当前已部署版本升级，验证数据、线路、价格、令牌摘要和历史记录保留。
- 使用第二个 Compose 项目建立独立站点，确认端口、数据库、令牌和产品互不串线。
- 记录镜像摘要、数据库版本、合同版本、运行命令和清理结果。
- 在 Windows + WSL 2 和原生 Linux 各运行一次预检与冒烟。
