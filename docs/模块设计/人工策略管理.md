# 人工策略管理模块设计

> 模块定位：由运营人员维护各站点的固定 Auto 成员、启停和分组入口开放状态，并保存策略历史及线路引用
> 对应代码：`internal/domain/operations`、`internal/application/operations`、`internal/adapters/storage/postgres/operations_strategy.go`、`internal/adapters/storage/postgres/operations_plan.go`、`internal/transport/http/operations*.go`、`api/operations.yaml`
> 所属里程碑：[M1 - 跑通多站人工运营闭环](../roadmap.md#m1)
> 当前状态：已完成
> 最近更新时间：2026-09-05
> 架构依据：[内部分层](../架构设计.md#7-manyrouter-内部分层)、[策略管理](../架构设计.md#87-策略管理)、[分组映射](../架构设计.md#12-new-api-分组映射)、[策略架构](../架构设计.md#18-策略架构)

## 1. 职责与边界

- 提供最低价、低延迟、高 SLA、高质量、均衡五种固定 Auto 类型。
- 按站点保存启用状态、入口开放状态、展示名称和人工选择的供应商成员。
- 检查成员所属站点及启用条件，保存版本、修改原因和操作者。
- 将策略交给[单站线路方案](./单站线路方案.md)，生成包含全部供应商和 Auto 的站点配置。
- 专属入口开放状态沿用[站点与供应商接入](./站点与供应商接入.md)的投放关系，保持与 Auto 参与情况独立。

五种名称表达产品偏好，M1 成员由运营人员选择。评分、模型真实性自动测评和自动成员调整尚未接入；M2 提供观测与评分建议，M3 实现自动准入、退出和恢复。

售价由[稳定价格管理](./稳定价格管理.md)负责；New API 调用及实际结果由 [New API 同步与核对](./New%20API同步与核对.md)负责。策略模块不处理用户请求、用户密钥、计费或供应商密钥明文。

## 2. 结构与数据流

### 2.1 当前目录

| 位置 | 当前职责 |
|---|---|
| `internal/domain/operations/types.go`、`validation.go` | 策略输入、五种类型、稳定组名、版本与成员基本校验 |
| `internal/application/operations/service.go`、`prepare.go` | 运营查询和修改入口、输入校验、重复提交处理准备 |
| `internal/adapters/storage/postgres/operations_strategy.go` | 站点成员检查、当前策略与历史版本保存 |
| `internal/adapters/storage/postgres/operations_transaction.go` | 配置事务、并发保护、审计、重复请求结果及受影响站点 |
| `internal/adapters/storage/postgres/operations_plan.go` | 汇总策略、价格与供应商，生成完整线路并安排同步 |
| `internal/transport/http/operations*.go`、`api/operations.yaml` | 运营接口、必填字段检查和接口契约 |

当前在统一运营应用模块内按职责分文件，复用同一套事务能力；尚未拆出独立的策略应用目录。New API 具体字段仍留在网关适配层。

### 2.2 数据与版本

| 对象 | 当前保存内容 |
|---|---|
| 站点策略 | 站点、类型、稳定组名、展示名、启用与入口开放状态、版本和时间；同站同类型唯一 |
| 人工成员 | 策略与站点供应商关系；拒绝跨站和重复成员 |
| 策略历史 | 每次保存的完整输入、版本、原因、操作者和时间；追加保存 |
| 线路引用 | 完整站点快照记录所用策略身份与版本，并保存实际共享组成员 |

专属入口开放状态只有投放关系这一份当前来源，通过投放修改接口保存。

### 2.3 保存流程

```text
读取站点当前策略与投放关系
    -> 人工选择成员、启用及入口开放状态
    -> 提交当前版本、修改原因和请求编号
    -> 校验成员与价格条件
    -> 同一事务保存策略历史、站点线路、同步任务和审计
    -> 各站分别同步并重读核对
    -> 查询线路与同步结果
```

尚无独立变更预览接口。保存接口返回策略本体；生成的线路及执行结果从线路和同步列表查看。

当前版本不匹配时拒绝保存。相同请求编号及相同内容在有效记录期内复用已保存结果；换用新请求编号再次提交相同策略内容，仍会生成下一策略版本。当前没有按策略内容去重。

首次创建固定 Auto 时，在持久化策略前读取目标 New API 的真实状态。若目标短码已经出现在分组倍率、用户入口或任一渠道的分组成员中，立即拒绝保存，避免把人工维护的同名组认领为受管 Auto。已有策略更新跳过这次占用检查，继续使用自身已保存的组键。

## 3. 当前业务规则

### 3.1 站点与成员

- 五种类型统一定义，尚未保存的站点策略视为未启用；各站分别保存名称、成员、入口开放状态及价格。
- 策略业务身份由站点身份和策略类型共同确定；下发到独立 New API 实例的 4 字符短码只由策略类型固定，修改展示名不会更换短码。
- 首次保存使用版本 `0`，以后携带已读取的版本。启用、停用与调整成员共用保存接口，暂不提供物理删除。
- 保存的成员必须属于目标站点。启用策略时，所选投放关系必须已经启用且同步成功，供应商全局状态也必须启用。
- 启用策略至少选择一个成员，并要求该共享组已经有发布或确认过的价格版本。首次配置可先保存停用策略，再创建并发布售价，最后启用。
- 当前按供应商整条受管渠道加入 Auto，渠道的全部模型共同参与。没有按组分别裁剪同一渠道模型的能力。
- 目前未校验每个模型是否具有单独确认的销售金额，也未实现新增模型的价格覆盖范围检查，不能把“存在组价格版本”解释为每个模型报价已经验证。

### 3.2 停用与恢复

- 一家供应商可以参与多个 Auto，同时保留专属组；从一个 Auto 移除成员不会更改其他组的人工选择。
- 生成线路时，只将仍被选中、策略启用且当前渠道期望启用的成员加入共享组。
- 供应商或投放停用会使渠道退出有效 Auto 池，人工成员选择仍保留。恢复投放后，保留在启用策略中的选择可能重新进入下一份线路；需要持续退出某个 Auto 时应在策略中移除成员。
- 所有成员都不可用时，共享组入口关闭，但保存的策略启用意图和历史选择仍保留。
- 停用 Auto 会移除该共享组的有效成员并关闭入口，保留组身份、价格及历史；已有绑定该组的 API Key 后续请求被拒绝。

### 3.3 共享组映射

- 每个 Auto 使用普通共享分组，渠道同时属于其专属组及人工选定的共享组。
- New API 的渠道 `group` 字段以逗号拼接全部分组，真实验收确认该字段最多容纳 64 个字符。现有 37 字符专属组键继续保留，避免已有渠道、价格和用户 Key 更换身份。
- 五种固定 Auto 在每个独立 New API 实例内各使用一个稳定的 4 字符短码。ManyRouter 仍按 `site_id + 策略类型` 保存策略身份、价格和历史，同一短码在不同站点实例中不会串线。
- 单条渠道最多同时属于 1 个专属组和 5 个固定 Auto；按现有专属组键计算，连同 5 个逗号共 62 个字符，低于 New API 的 64 字符上限。
- ManyRouter 的固定 Auto 不使用 New API 自带的 `auto` 虚拟选组列表，原有列表保持原值。
- New API 优先级与权重属于渠道，同一渠道加入多个组后各组复用这些值。
- M1 受管渠道统一使用优先级 `0`、权重 `100`。五种策略当前通过人工选择不同成员池体现差异，没有每组独立权重或自动排序。

短码只在单个 New API 实例内解释。M1 的跨站隔离因此要求每个站点连接独立实例；若未来允许多个 ManyRouter 站点共享一个实例，必须先重新设计分组命名空间。M5 用户自定义 Auto 的数量和名称不具备固定上限，实施前还需定义容量预算、超限处理和兼容迁移，不能直接沿用本期拼接方式。

| 固定 Auto | New API 短码 |
|---|---|
| 最低价 | `mrap` |
| 低延迟 | `mral` |
| 高 SLA | `mras` |
| 高质量 | `mraq` |
| 均衡 | `mrab` |

升级前已经存在的 `mr_a_...` 当前策略继续使用原 `group_key`，对应旧价格和后续生成的线路也沿用该键；旧线路快照继续支持读取和校验，历史证据不改写。首次创建的新策略使用上表短码，并在保存前完成真实站占用检查。

产品运行时和验收程序都不自动批量迁移旧策略。本次修复期间仅对隔离验收库里由失败验收产生、尚未交付用户的记录执行过一次性迁移；正常环境和后续验收继续沿用旧策略原组键。

## 4. 入口开放与关闭

用户已确认沿用 New API 现有接口，将此项能力统一定义为“开放入口 / 关闭入口”：

- 关闭专属入口后，用户不能再选择该组，已有绑定该组的 API Key 后续请求也被拒绝。供应商、渠道、组身份、成员选择和价格历史继续保留。
- 关闭专属入口不影响该供应商参与其他已开放的 Auto。需要同时停止全部相关调用时，执行供应商或投放停用。
- 固定 Auto 入口采用相同规则，关闭后已有绑定该 Auto 组的 API Key 后续请求被拒绝；成员在专属组或其他已开放 Auto 中的服务不受该入口关闭影响。
- 重新开放入口后，仍按当前有效策略、线路和用户权限处理请求，不自动恢复已经停用的供应商或渠道。
- 底层 JSON 和数据库字段 `visible` 保留兼容，`true` 表示入口开放，`false` 表示入口关闭。界面与业务描述不再把它解释为只影响页面呈现。

适配器通过 `UserUsableGroups` 维护入口开放状态。真实 New API 合同已经确认关闭专属入口后已有组 Key 返回 HTTP 403；该权限行为已由用户接受，无需增加仅控制页面呈现的新接口。各站仍需核对入口开关与其他产品服务彼此独立。

## 5. 接口与协作

| 接口 | 当前能力 |
|---|---|
| `GET /api/v1/ops/strategies` | 按站点查询已保存策略、成员和价格倍率 |
| `PUT /api/v1/ops/sites/{id}/strategies/{kind}` | 保存成员、启用、入口开放状态、名称及新策略版本 |
| `PUT /api/v1/ops/relations/{id}` | 开放或关闭专属入口，并修改投放状态 |
| `GET /api/v1/ops/plans`、`GET /api/v1/ops/plans/{id}` | 查看策略版本引用、完整配置及前一份快照 |
| `GET /api/v1/ops/sync-operations` | 查看逐站同步与步骤结果 |

写操作要求版本、原因和重复提交编号；启用、入口开放状态等布尔字段必须明确提供，遗漏或填写空值会被拒绝。身份检查复用[运营账号与权限](./运营账号与权限.md)，页面由[运营控制台](./运营控制台.md)负责。

## 6. 关键决策

1. 在统一运营模块中按职责拆分，复用现有数据库、事务和后台任务。
2. 策略历史与价格历史分别保存，成员修改不自动重算倍率。
3. 当前使用整渠道成员和统一权重，保持配置与 New API 的实际能力相符。
4. 保存成功表示接收了运营修改，生效必须看目标站点实际核对结果。
5. 沿用 New API 现有入口权限：关闭专属或 Auto 入口会拒绝已有组 Key 的后续请求，保留渠道和历史。
6. 保留既有专属组身份，固定 Auto 改用实例内 4 字符短码，使最坏分组组合仍能写入 New API 的 64 字符字段。
7. 新建固定 Auto 前读取真实站并拒绝占用短码；已有策略保留自身组键及价格，兼容升级前的 `mr_a_...` 配置。

## 7. 当前实现

已实现五种固定类型、按站点保存成员与启停、版本冲突检查、策略历史、线路快照中的策略引用、同步任务和运营审计。接口及控制台已接入这些能力。

首次创建固定 Auto 已接入真实站短码占用检查，覆盖倍率、用户入口和渠道成员；已有策略更新保留数据库中的现有组键并跳过首次占用检查。升级前的 `mr_a_...` 当前策略可以继续使用原价格并生成后续线路。

固定 Auto 的分组长度修复和 HTTP 429 可重试分类已完成复验，[最终真实验收](../验收/M1-真实验收-2026-09-05.json)全部通过。3 个独立供应商记录来自 1 个真实上游，分别投放到 2 个独立 New API 实例；不同成员与售价、专属和 Auto 调用、实际用量增长、入口关闭后 403 与重新开放、历史恢复及单站失败隔离均符合预期，M1 人工策略模块已完成。

按内容去重、独立预览接口、逐模型报价覆盖校验和自动评分调整仍属待扩展能力。此次多记录结果不能用作多个真实厂商在成本、能力或故障上的差异证据。

## 8. 验证方式

- 规则与应用测试：`internal/domain/operations/validation_test.go`、`internal/application/operations/service_test.go`。
- 首次策略检查测试覆盖短码已存在于倍率、用户入口和渠道成员三种冲突，以及无冲突时保存；已有策略更新验证不会重复执行首次占用检查。
- HTTP 测试：`internal/transport/http/operations_test.go`、`operations_input_test.go`，覆盖路由、版本与成员传递、必填状态和错误响应。
- 数据库测试：`internal/adapters/storage/postgres/operations_integration_test.go`，覆盖双站配置和人工策略；`operations_review_integration_test.go` 覆盖历史恢复后保留停用策略成员选择。
- 旧策略集成测试覆盖 `mr_a_...` 当前策略更新后仍保留原组键、复用原价格，并把该组键写入新线路快照。
- 同步测试：`internal/application/reconciliation/site_service_test.go`，覆盖共享组、原有组保留、过期计划及部分失败。
- 分组容量验证：专属组稳定键保持不变，五种固定 Auto 短码各为 4 个字符；验证单条渠道加入全部五种 Auto 后，含逗号的 `group` 字符串不超过 64 个字符。
- 已通过真实验收：两个独立 New API 实例中的人工策略保存、专属与 Auto 调用、实际用量增长、入口关闭后拒绝已有组 Key，以及重新开放后恢复调用。
- 最终真实验收已通过：价格与成员隔离的最终重读、成员调整后售价保持、历史恢复，以及单站失败隔离和恢复；HTTP 429 按可重试错误处理后完成全部检查。

## 9. 待扩展项

- 变更前独立预览、受影响模型提示、逐模型价格范围校验和按内容去重。
- 独立策略历史查询界面；当前历史已存储，线路快照保留版本引用。
- M2 评分建议、M3 自动准入与退出、M5 用户自定义策略。
- 为用户自定义 Auto 设计明确的分组字段容量方案，包括数量上限、短码分配、冲突检查、超限提示和已有组迁移。
