## 1. 职责与边界

本模块负责把 ManyRouter 连接到一个已经部署的 New API 站点，并让运营人员只在 ManyRouter 中完成一次供应商录入。模块需要维护站点登记、供应商资料、供应商与站点的启用关系，以及受管资源的同步状态。

供应商资料包括服务地址、访问凭证、支持的协议和模型、平台确认的采购价格及运营状态。供应商在 ManyRouter 中维护一份有效资料，后续多站点复用能力由 M1 扩展。

接入供应商后，ManyRouter 为目标站点生成供应商专属分组、对应渠道和价格，并通过 New API 的管理能力完成创建、更新、启停和结果核对。用户最终仍通过 New API 的 API Key 调用真实模型。

本模块不负责真实流量的完整增量采集、主动测评、评分计算、自动准入和自动退出。固定 Auto 的自动运营、用户自定义 Auto、用户侧 ManyRouter 页面和正式批量接入端点属于后续里程碑。

## 2. 结构与数据流

```text
运营人员
   │
   ▼
ManyRouter 站点与供应商录入
   │
   ▼
生成站点供应商关系与期望配置
   │
   ▼
New API 适配层调用管理接口
   │
   ▼
创建或更新渠道、供应商专属分组和价格
   │
   ▼
重新读取 New API 实际状态并核对
   │
   ├─ 一致：记录已生效与审计结果
   └─ 有差异：保留待同步状态并重试或告警
   ```

真实用户请求仍由 New API 处理：New API 负责用户鉴权、额度、计费、协议转换、渠道选择、转发和日志。ManyRouter 停止或暂时不可用时，New API 继续使用最后一次确认的配置。

M0 的配置写入使用 New API 已有的 HTTP 管理接口；ManyRouter 不连接 New API 业务主库，也不直接写入 New API 数据表。站点兼容状态和受管资源的期望、实际、最近确认结果分别可查询。

## 3. 关键决策

- ManyRouter 是受管供应商、专属分组和期望线路的管理入口，运营人员不需要再进入 New API 重复创建这些资源。
- 一个供应商在一个站点对应一个稳定的供应商专属分组。展示名称可以调整，内部绑定不能依靠名称模糊匹配。
- New API 的渠道、分组和价格属于执行状态；ManyRouter 保存业务上的期望状态，写入后必须重新读取核对。
- 只修改 ManyRouter 创建或明确接管的资源，不触碰 New API 中的非受管渠道、分组和其他配置。
- 配置写入支持重复执行。重试同一项接入不得创建重复渠道、重复分组或重复价格。
- 供应商访问凭证由 ManyRouter 保护和管理，日志、任务记录和审计中只能保留脱敏结果或凭证版本。
- New API 版本先做能力检查；未经验证或能力不满足的站点只能保留当前配置并告警。
- 供应商专属分组在首次接入后先用于观察，是否进入 Auto 由后续评估和策略里程碑决定。

## 4. 当前实现

当前尚未实现本模块代码。ManyRouter 尚无可运行的 Go 服务、数据库迁移、控制台或 New API 适配实现。

规划中的职责分布如下：

- 站点与供应商领域模块保存业务规则和站点供应商关系。
- 接入用例负责一次录入后生成目标站点的受管资源计划。
- New API 网关适配层负责版本识别、管理接口调用、错误转换和实际状态读取。
- 同步与核对用例负责顺序应用、重试、幂等和结果记录。
- 运营控制台提供首站登记、供应商录入、价格配置和同步结果查看。

## 5. 验证方式

退出 M0 前必须使用真实 New API 进程、真实数据库和至少一个真实可调用的供应商完成验证，不能用模拟响应代替业务结论。

- 能登记一个受支持版本的 New API 站点，并完成能力检查。
- 在 ManyRouter 中录入一个真实供应商后，目标 New API 自动出现可用渠道、供应商专属分组和价格。
- 用户创建绑定供应商专属分组的 API Key，完成一次真实模型调用和计费记录。
- 重复执行接入和同步后，资源数量、分组关系和价格保持正确，不产生重复资源。
- New API 管理接口暂时不可达时，已有调用继续使用最后一次有效配置；恢复后可以继续同步和核对。
- 同步失败时能区分已完成和未完成结果，并保留重试或人工处理记录。
- 未经支持的 New API 版本能被识别并告警，禁止在能力未知时盲目写入。
- 运营账号、站点管理凭证和供应商访问凭证不会出现在普通返回、日志或审计正文中。

## 6. 待扩展项

- M1 将同一套供应商资料投放到多个站点，并按站点维护策略、价格和同步结果。
- M2 将增加独立日志库只读采集、测量事实和影子评分。
- M3 将基于评分自动维护固定 Auto 成员、停用和恢复。
- M3 将补齐固定 Auto 自动运营和 New API 用户侧数据展示。
- M4 将补齐正式批量同步、兼容矩阵和可复制发布。
- M5 将支持用户自定义 Auto、报价确认和策略快照。
